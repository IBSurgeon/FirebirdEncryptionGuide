[[fbcrypt-install]]
= Installation of the encryption plugin

Firebird 3.0 (from 3.0.3), 4.0 and 5.0 are supported. Firebird 2.5 is not supported: it does not have the encryption plugin interface.

[NOTE]
====
If you have HQbird, you do not need to download the plugin archive or copy its files: HQbird already contains them. You need only the license file `DbCrypt.conf` and the `KeyHolderPlugin` parameter. See <<fbcrypt-install-hqbird>>.
====

The installation has the same steps for all platforms:

. Copy the plugin files to the Firebird folder.
. Put the license file `DbCrypt.conf` into the `plugins` folder.
. Set the parameter `KeyHolderPlugin = KeyHolder` in `firebird.conf` or `databases.conf`.
. Restart Firebird.
. Test encryption on a test database.

[[fbcrypt-install-hqbird]]
== If HQbird is installed

HQbird already contains the files of the encryption plugin for the server and for workstations. You do not need to run the installation scripts. You do not need to download the plugin archive. You do not need to copy the `Server` and `Client` folders from the archive.

.Plugin files in HQbird for Windows
[cols="1,1", options="header"]
|===
| Files | Folder

| Server plugins `dbcrypt.dll`, `keyholder.dll`, `keyholderstdin.dll`
| `C:\HQbird\Firebird<NN>\plugins`

| Libraries `fbclient.dll` and `fbcrypt.dll`, utilities `gbak`, `nbackup`, `isql`, `gfix`
| `C:\HQbird\Firebird<NN>`

| Client files for workstations: `fbclient.dll`, `fbcrypt.dll`, OpenSSL, `plugins\keyholder.dll`, `plugins\keyholderstdin.dll`, `plugins\dbcrypt.dll`
| `C:\HQbird\ClientLibs\<bitness>\<version>`, for example `C:\HQbird\ClientLibs\64\5.0`
|===

Here `C:\HQbird` is the default installation folder, and `<NN>` is `30`, `40` or `50`.

What you must do:

. Put the license file `DbCrypt.conf` into the `plugins` folder of the server.
. Set the parameter `KeyHolderPlugin = KeyHolder` in `firebird.conf` or `databases.conf`. In the `firebird.conf` file of HQbird this parameter is a comment line.
. Restart Firebird.
. Encrypt the database: see <<fbcrypt-usage>>.
. For a workstation, take the files from the `ClientLibs` folder with the correct bitness and version. In the `firebird.conf` file near `fbclient.dll`, set `KeyHolderPlugin = KeyHolder`.

HQbird does not contain the test library `KeySource.dll` and the script `run-tests.ps1`. They are only in the plugin archive and are necessary only for tests.

[NOTE]
====
The 64-bit client plugin `KeyHolder` needs the OpenSSL library with the name `libcrypto-1_1-x64.dll` near `fbclient.dll`. If the folder `ClientLibs\64\5.0` does not contain this file, copy it from the folder `ClientLibs\64\4.0`. Without this file the connection fails with the error `Key not set`, even when the library `KeySource.dll` returned the correct key.
====

== Windows

=== Installation of the encryption plugin on Windows with a script

Download 2 files from https://github.com/IBSurgeon/FirebirdEncryptionPluginInstall/tree/main/ForWindows: `install-Firebird-encryption-plugin.bat` and `inst-crypt-plugin.ps1`

To make the deployment of the encryption plugin simpler, we prepared a PowerShell script. It automatically finds the installed Firebird instances, downloads the necessary archive with the plugin, extracts the archive, changes the configuration file and runs encryption tests to check that the plugin works.

Open the `cmd` command prompt as administrator and go to the folder that contains the `install-Firebird-encryption-plugin.bat` script.

[source,cmd]
----
cd d:\IBase\crypt-plugin
----

Now you can run the plugin installation script:

[source,cmd]
----
install-Firebird-encryption-plugin.bat
----

The script shows this message:

----
This script will install Firebird crypt plugin.
Now script will scan OS registry for Firebird installations.
You can run script silently adding --crypt="c:\path\to\firebird" parameter
(Do not forget double-quotes in path like "C:\Program Files", etc...)
Press Enter to continue or Ctrl+C to exit script.
----

If you press `Enter`, the installer looks for the installed Firebird in the registry and asks you to select the instance for the plugin installation. It checks that the Firebird version is compatible (3.0.3+, 4.0.x, 5.0.x).

You can also press `Ctrl+C`, exit and run the command again with an additional switch.

First, let us press Enter.

install-Firebird-encryption-plugin.bat --crypt="C:\Firebird\5.0"

The installer downloads the necessary files (dll files, configuration files and the trial license), and then saves them to the selected Firebird folder.

The installer changes `firebird.conf`: it adds the line `KeyHolderPlugin = KeyHolder`

* *Restart of Firebird (be careful in a production environment!)* +
The installer restarts the Firebird instance. At this step Firebird is ready to encrypt databases with the trial license.

* *Creates folders with files for client applications* +
The installer creates a folder with the client files in the folder where it was started: `Client\32bit` and `Client\64bit`.

=== Manual installation

In some cases, the installation with the script is not possible, for example if Firebird works on a non-standard port. In this case you can install the encryption plugin manually. Download the zip archive of the installer for the applicable version from one of these addresses:

* https://cc.ib-aid.com/download/distr/crypt/CryptPlugin-FB_30_WINDOWS_64bit.zip
* https://cc.ib-aid.com/download/distr/crypt/CryptPlugin-FB_40_WINDOWS_64bit.zip
* https://cc.ib-aid.com/download/distr/crypt/CryptPlugin-FB_50_WINDOWS_64bit.zip

This is the content of the archive for Firebird 5.0 from 26.11.2026. The archives of this date contain the files of HQbird 3.0.15.33894, 4.0.8.3332 and 5.0.5.1979, and a trial license that is valid until 31.12.2026. The archive for Firebird 3.0 has different ICU libraries (`icu*52`) and C++ libraries (`msvcp100.dll`, `msvcr100.dll`).

The `Server` folder in the archive contains binary files *ONLY* for the x64 architecture. It assumes that the server installation has this architecture, which is almost always true. The `Client` folder in the archive contains binary files both for the x86 (32bit) and for the x64 (64bit) architecture.

Extract the files from the `Server` folder to the root folder of the Firebird server. Some Firebird binary files are replaced. Stop the Firebird service before you copy the files.

The `Client` folder contains two subfolders `Client\32bit` and `Client\64bit`. You can use the files from these folders to develop an application that uses encryption: copy all files from this folder to the folder that contains the executable file of your application. It is very important to use the supplied `fbclient.dll` file.

The `key-plugins` folder contains two key sources. Copy the necessary file yourself:

[cols="2,3,4", options="header"]
|===
| File | Where to copy | Purpose
| `KeySource.dll` | to the client folder, near `fbclient.dll` | Test library with test keys. The application and the utilities get the key without switches. See <<fbcrypt-keysource>>.
| `keyholderstdin.dll` | to the client `plugins` folder | The `KeyHolderStdin` plugin: the utility reads the key from the input stream. See <<fbcrypt-utils-stdin>>.
|===

Without the copy, a utility with the switch `-KeyHolder KeyHolderStdin` reports `Key holder plugin KeyHolderStdin failed to load`.

The `Client/db-crypt` folder contains a script to test encryption and a test database.

==== Configuration

After you extract the archive, you must configure Firebird.

To turn on the database encryption plugin and the key management, set the name of the key holder plugin in the `firebird.conf` configuration file:

[source,conf]
----
KeyHolderPlugin = KeyHolder
----

Or, alternatively, set it for the alias of the encrypted database in the `databases.conf` file:

[source,conf]
----
myencrypted = C:\Temp\EMPLOYEE30\EMPLOYEE30.FDB
{
    KeyHolderPlugin = KeyHolder
}
----

In the second case, connect to the database by the alias (`localhost:myencrypted`).

After you change the configuration, restart the Firebird service.

==== Testing

After the installation and configuration, you can run a series of tests to check that encryption and decryption work. The tests are in the `Client/db-crypt` folder.

[NOTE]
====
In the archives from 01.10.2026 and later, there is one script `run-tests.ps1` instead of the files `01-encrypt.bat` ... `05-gfix.bat`. It runs the same steps two times: with the key from the `KeySource.dll` library and with the key from the input stream (the `KeyHolderStdin` plugin). Before each pass, the script copies the necessary file from the `key-plugins` folder and changes the `KeyHolderPlugin` parameter in the client `firebird.conf` file. The commands that it runs are described below.
====

[WARNING]
====
All tests use test keys. If in your installation the test keys are in the file `%root%/plugins/KeyHolder.conf`, this file is only for test purposes. Do not forget to rename or delete it when you complete the tests.
====

== Linux

The scripts to install Firebird and the encryption plugin on Linux are at https://github.com/IBSurgeon/firebirdlinuxinstall

To install on "vanilla" Firebird versions, use one of the scripts with the name `fb_vanilla-<version>.sh`. For example, for Firebird 5.0 this is the file https://raw.githubusercontent.com/IBSurgeon/firebirdlinuxinstall/refs/heads/main/fb_vanilla-50.sh[fb_vanilla-50.sh].

[source,bash]
----
wget https://raw.githubusercontent.com/IBSurgeon/firebirdlinuxinstall/refs/heads/main/fb_vanilla-50.sh
chmod +x fb_vanilla-50.sh
sudo ./fb_vanilla-50.sh
----

The script shows this message:

----
This program will install Firebird 5.0 on this computer
    Command line switches:
    --debug - also install debug information, takes more traffic;
    --crypt - install and configure crypto plugin
    --crypt-only[=/path/to/firebird] - install and configure ONLY crypto plugin without Firebird
Press Enter to start installation or ^C to abort
----

The `--crypt` switch installs Firebird together with the encryption plugin. The `--crypt-only` switch installs only the plugin into an already installed Firebird:

[source,bash]
----
sudo ./fb_vanilla-50.sh --crypt-only=/opt/firebird
----

[NOTE]
====
The script does not install the OpenSSL 1.1 compatibility package and does not create a file with the keys. If encryption does not start after the script, do the manual installation steps described below.
====

=== Manual installation on Linux

The steps below were tested on AlmaLinux 9 with Firebird 3.0, 4.0 and 5.0, installed in `/opt/firebird`. Run all commands as `root`.

Differences between the versions:

[cols="3,1,1,1", options="header"]
|===
| | FB 3.0 | FB 4.0 | FB 5.0
| Archive `CryptPlugin-FB_<V>_LINUX_64bit.tar.xz` | `30` | `40` | `50`
| OpenSSL 1.1 is necessary | yes | yes | no (OpenSSL 3)
| systemd service name | `firebird-superserver` | `firebird` | `firebird`
| Encrypted backup with the standard `gbak` | no | yes | yes
| `MON$DATABASE.MON$CRYPT_STATE` | no | yes | yes
|===

.Step 1. Set the version
[source,bash]
----
V=50      # 30 = Firebird 3.0, 40 = Firebird 4.0, 50 = Firebird 5.0
FB=/opt/firebird
----

.Step 2. Download and extract the archive
[source,bash]
----
cd /root
curl -LO https://cc.ib-aid.com/download/distr/crypt/CryptPlugin-FB_${V}_LINUX_64bit.tar.xz
mkdir -p /root/crypt
tar xJf CryptPlugin-FB_${V}_LINUX_64bit.tar.xz -C /root/crypt --strip-components=1
ls /root/crypt/Server/plugins
----

The `Server/plugins` folder contains the files `libDbCrypt.so`, `libKeyHolder.so` and `DbCrypt.conf` (the trial license). The `Client` folder contains the client utilities and libraries.

.Step 3. Install OpenSSL 1.1 (only Firebird 3.0 and 4.0)
[source,bash]
----
dnf install -y compat-openssl11
ls /usr/lib64/libcrypto.so.1.1
----

The plugins for Firebird 3.0 and 4.0 load `libcrypto.so.1.1`. Without this library, the `ALTER DATABASE ENCRYPT` statement fails with the error `Library libcrypto.so.1.1 failed to load`. In Debian and Ubuntu the package has a different name. Install the package that contains `libcrypto.so.1.1`.

Ubuntu 22.04 and 24.04 have no package with OpenSSL 1.1 in the standard repositories. In the test of the archives from 26.11.2026 on Ubuntu 24.04, the package `libssl1.1` of Ubuntu 20.04 was installed with `dpkg -i`. With this package, the script `Client/db-crypt/run-tests.sh` passed for Firebird 3.0, 4.0 and 5.0. In Debian and Ubuntu the library is in the folder `/usr/lib/x86_64-linux-gnu`.

.Step 4. Copy the plugin files
[source,bash]
----
cp /root/crypt/Server/plugins/* $FB/plugins/
ls -l $FB/plugins | grep -iE 'crypt|key'
----

.Step 5. Create a file with the key (for the test)
[source,bash]
----
KEY=$(openssl rand -hex 32 | sed 's/../0x&,/g')
echo "Key=Red $KEY" > $FB/plugins/KeyHolder.conf
chown root:firebird $FB/plugins/KeyHolder.conf
chmod 640 $FB/plugins/KeyHolder.conf
----

Keep a copy of the key outside the server. A file with the key on the same disk as the database is good only for tests and development.

.Step 6. Turn on the key holder plugin

For one database (`databases.conf`):

[source,bash]
----
cat >> $FB/databases.conf <<'EOF'

employee = /opt/firebird/examples/empbuild/employee.fdb
{
    KeyHolderPlugin = KeyHolder
}
EOF
----

Or for all databases (`firebird.conf`):

[source,bash]
----
echo "KeyHolderPlugin = KeyHolder" >> $FB/firebird.conf
----

The second variant is necessary if you restore an encrypted backup to a new file.

.Step 7. Restart Firebird
[source,bash]
----
# Firebird 3.0:
systemctl restart firebird-superserver
# Firebird 4.0 and 5.0:
systemctl restart firebird
----

.Step 8. Encrypt the test database
[source,bash]
----
$FB/bin/isql localhost:employee -user SYSDBA -password masterkey <<'EOF'
alter database encrypt with "DbCrypt" key Red;
commit;
show database;
EOF
----

On Linux the plugin name `"DbCrypt"` is case sensitive. Do not remove the double quotes.

.Step 9. Check the result
[source,bash]
----
$FB/bin/gstat -h /opt/firebird/examples/empbuild/employee.fdb | grep -iE 'attrib|key name'
#   Attributes      force write, encrypted, plugin DbCrypt
#   Encryption key name:    RED
----

.Step 10. Check that the key is necessary
[source,bash]
----
mv $FB/plugins/KeyHolder.conf $FB/plugins/KeyHolder.conf.off
systemctl restart firebird            # firebird-superserver for 3.0
echo "select count(*) from employee;" | $FB/bin/isql localhost:employee -user SYSDBA -password masterkey
#   Statement failed, SQLSTATE = 08006
#   Invalid crypt key RED
#   -Key not set
mv $FB/plugins/KeyHolder.conf.off $FB/plugins/KeyHolder.conf
systemctl restart firebird            # firebird-superserver for 3.0
----

Backup on Linux is described in <<fbcrypt-utils-gbak>>.

== License file

The `DbCrypt` plugin works only with the license file `plugins/DbCrypt.conf`. The archives contain a trial license with a limited validity period. For a production system, replace the file with the license that you got from IBSurgeon, and restart Firebird.

The license file is necessary in all places where the `DbCrypt` plugin is loaded: on the server and near the `gbak` utility that creates encrypted backups.

The file parameters are described in <<fbcrypt-config-dbcrypt>>.
