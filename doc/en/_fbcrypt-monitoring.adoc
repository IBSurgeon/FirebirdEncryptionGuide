[[fbcrypt-monitoring]]
= How to monitor the encryption progress

Firebird encrypts the database only when it has active connections. The encryption process runs in a separate parallel thread. For large databases, the full encryption can take a long time.

== The MON$DATABASE table

To monitor the encryption process, run an SQL query on the monitoring table `MON$DATABASE`:

[source,sql]
----
select mon$crypt_page * 100.0 / mon$pages as Percent from mon$database;
commit;
----

The `MON$CRYPT_PAGE` field contains the number of the page that the encryption thread reached. When the encryption is complete, the field is `0`.

The monitoring tables show a snapshot at the time of the first access in the transaction. To see a new value, end the transaction (`commit`) and run the query again.

In Firebird 4.0 and 5.0 there is also the `MON$CRYPT_STATE` field:

[source,sql]
----
select mon$crypt_state from mon$database;
----

[cols="1,3", options="header"]
|===
| Value | State
| `0` | the database is not encrypted
| `1` | the database is encrypted
| `2` | decryption is in progress
| `3` | encryption is in progress
|===

== isql

The `show database` command shows one of these lines:

[cols="2,3", options="header"]
|===
| Line | State
| `Database not encrypted` | the database is not encrypted
| `Database encrypted, crypt thread not complete` | the encryption is started, but not complete
| `Database encrypted` | the encryption is complete
|===

== gstat

The `gstat -h` command shows the header attributes: the `encrypted` flag, the plugin name and the key name. It works fast.

Note that the `gstat -e` command can take a long time: the utility reads all pages of the database.

== If the encryption does not progress

* Check that there is at least one connection to the database. Without connections, the encryption thread does not work.
* Check that the connection sent the key, or that the key is available to the server.
* Look at the messages in `firebird.log`.
