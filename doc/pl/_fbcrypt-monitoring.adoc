[[fbcrypt-monitoring]]
= Jak śledzić postęp szyfrowania

Firebird szyfruje bazę danych tylko wtedy, gdy ma ona aktywne połączenia. Proces szyfrowania jest wykonywany w osobnym, równoległym wątku. Dla dużych baz danych pełne szyfrowanie może zająć dużo czasu.

== Tabela MON$DATABASE

Aby śledzić proces szyfrowania, wykonaj zapytanie SQL do tabeli monitorowania `MON$DATABASE`:

[source,sql]
----
select mon$crypt_page * 100.0 / mon$pages as Percent from mon$database;
commit;
----

Pole `MON$CRYPT_PAGE` zawiera numer strony, do której doszedł wątek szyfrowania. Gdy szyfrowanie się zakończy, pole ma wartość `0`.

Tabele monitorowania pokazują stan z chwili pierwszego odwołania w transakcji. Aby zobaczyć nową wartość, zakończ transakcję (`commit`) i wykonaj zapytanie ponownie.

W Firebird 4.0 i 5.0 jest też pole `MON$CRYPT_STATE`:

[source,sql]
----
select mon$crypt_state from mon$database;
----

[cols="1,3", options="header"]
|===
| Wartość | Stan
| `0` | baza danych nie jest zaszyfrowana
| `1` | baza danych jest zaszyfrowana
| `2` | trwa odszyfrowywanie
| `3` | trwa szyfrowanie
|===

== isql

Polecenie `show database` wyświetla jeden z wierszy:

[cols="2,3", options="header"]
|===
| Wiersz | Stan
| `Database not encrypted` | baza danych nie jest zaszyfrowana
| `Database encrypted, crypt thread not complete` | szyfrowanie uruchomiono, ale się nie zakończyło
| `Database encrypted` | szyfrowanie się zakończyło
|===

== gstat

Polecenie `gstat -h` pokazuje atrybuty nagłówka: znacznik `encrypted`, nazwę wtyczki i nazwę klucza. Działa szybko.

== Jeśli szyfrowanie nie postępuje

* Sprawdź, czy z bazą danych jest co najmniej jedno połączenie. Bez połączeń wątek szyfrowania nie działa.
* Sprawdź, czy połączenie przekazało klucz lub czy klucz jest dostępny dla serwera.
* Przejrzyj komunikaty w `firebird.log`.
