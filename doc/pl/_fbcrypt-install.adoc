[[fbcrypt-install]]
= Instalacja wtyczki szyfrowania

Obsługiwane są Firebird 3.0 (od wersji 3.0.3), 4.0 i 5.0. Firebird 2.5 nie jest obsługiwany: nie ma interfejsu wtyczek szyfrowania.

[NOTE]
====
Jeśli masz zainstalowany HQbird, nie trzeba pobierać archiwum wtyczki ani kopiować jego plików: HQbird już je zawiera. Potrzebne są tylko plik licencji `DbCrypt.conf` i parametr `KeyHolderPlugin`. Zobacz <<fbcrypt-install-hqbird>>.
====

Instalacja składa się z tych samych kroków na wszystkich platformach:

. Skopiować pliki wtyczki do folderu Firebird.
. Umieścić plik licencji `DbCrypt.conf` w folderze `plugins`.
. Ustawić parametr `KeyHolderPlugin = KeyHolder` w `firebird.conf` lub `databases.conf`.
. Uruchomić ponownie Firebird.
. Sprawdzić szyfrowanie na testowej bazie danych.

[[fbcrypt-install-hqbird]]
== Jeśli zainstalowany jest HQbird

HQbird zawiera już pliki wtyczki szyfrowania dla serwera i dla stanowisk roboczych. Nie trzeba uruchamiać skryptów instalacyjnych. Nie trzeba pobierać archiwum wtyczki. Nie trzeba kopiować folderów `Server` i `Client` z archiwum.

.Pliki wtyczki w HQbird dla systemu Windows
[cols="1,1", options="header"]
|===
| Pliki | Folder

| Wtyczki serwerowe `dbcrypt.dll`, `keyholder.dll`, `keyholderstdin.dll`
| `C:\HQbird\Firebird<NN>\plugins`

| Biblioteki `fbclient.dll` i `fbcrypt.dll`, narzędzia `gbak`, `nbackup`, `isql`, `gfix`
| `C:\HQbird\Firebird<NN>`

| Pliki klienckie dla stanowisk roboczych: `fbclient.dll`, `fbcrypt.dll`, OpenSSL, `plugins\keyholder.dll`, `plugins\keyholderstdin.dll`, `plugins\dbcrypt.dll`
| `C:\HQbird\ClientLibs\<architektura>\<wersja>`, na przykład `C:\HQbird\ClientLibs\64\5.0`
|===

Tutaj `C:\HQbird` to domyślny folder instalacji, a `<NN>` to `30`, `40` lub `50`.

Co trzeba zrobić:

. Umieść plik licencji `DbCrypt.conf` w folderze `plugins` serwera.
. Ustaw parametr `KeyHolderPlugin = KeyHolder` w pliku `firebird.conf` lub `databases.conf`. W pliku `firebird.conf` z HQbird ten parametr jest wierszem komentarza.
. Uruchom ponownie Firebird.
. Zaszyfruj bazę danych: zobacz <<fbcrypt-usage>>.
. Dla stanowiska roboczego weź pliki z folderu `ClientLibs` o właściwej architekturze i wersji. W pliku `firebird.conf` obok `fbclient.dll` ustaw `KeyHolderPlugin = KeyHolder`.

HQbird nie zawiera testowej biblioteki `KeySource.dll` ani skryptu `run-tests.ps1`. Są one tylko w archiwum wtyczki i są potrzebne tylko do testów.

[NOTE]
====
64-bitowa wtyczka kliencka `KeyHolder` potrzebuje biblioteki OpenSSL o nazwie `libcrypto-1_1-x64.dll` obok `fbclient.dll`. Jeśli w folderze `ClientLibs\64\5.0` nie ma tego pliku, skopiuj go z folderu `ClientLibs\64\4.0`. Bez tego pliku połączenie kończy się błędem `Key not set`, nawet gdy biblioteka `KeySource.dll` zwróciła poprawny klucz.
====

== Windows

=== Instalacja wtyczki szyfrowania w systemie Windows za pomocą skryptu

Pobierz 2 pliki z https://github.com/IBSurgeon/FirebirdEncryptionPluginInstall/tree/main/ForWindows: `install-Firebird-encryption-plugin.bat` i `inst-crypt-plugin.ps1`

Aby uprościć wdrożenie wtyczki szyfrowania, przygotowaliśmy skrypt w języku PowerShell. Skrypt automatycznie wyszukuje zainstalowane instancje Firebird, pobiera właściwe archiwum z wtyczką, rozpakowuje archiwum, wprowadza zmiany w pliku konfiguracyjnym i uruchamia testy szyfrowania, aby sprawdzić działanie wtyczki.

Uruchom wiersz poleceń `cmd` jako administrator i przejdź do folderu, w którym znajduje się skrypt `install-Firebird-encryption-plugin.bat`.

[source,cmd]
----
cd d:\IBase\crypt-plugin
----

Teraz można uruchomić skrypt instalacji wtyczki:

[source,cmd]
----
install-Firebird-encryption-plugin.bat
----

Zostanie wyświetlony następujący komunikat:

----
This script will install Firebird crypt plugin.
Now script will scan OS registry for Firebird installations.
You can run script silently adding --crypt="c:\path\to\firebird" parameter
(Do not forget double-quotes in path like "C:\Program Files", etc...)
Press Enter to continue or Ctrl+C to exit script.
----

Jeśli naciśniesz `Enter`, instalator wyszuka zainstalowany Firebird w rejestrze i zaproponuje wybór instancji, do której należy zainstalować wtyczkę. Instalator sprawdza, czy wersja Firebird jest zgodna (3.0.3+, 4.0.x, 5.0.x).

Możesz też nacisnąć `Ctrl+C`, wyjść i uruchomić polecenie ponownie z dodatkowym przełącznikiem.

Najpierw naciśnijmy Enter.

----

If you select service that is running
it will be restarted to install plugin
 -------------------------------------
1) Service Name: FirebirdServerDefaultInstance (Running, OK)
Installed in: C:\Firebird\5.0
Version: 5.0.4.1812 (64bit)
 -------------------------------------
0) Exit script
Enter number (0-1) and press Enter:
----

Zostaną wyświetlone znalezione instancje Firebird. Wybierz właściwą i naciśnij Enter (w tym przypadku należy wpisać 1 i nacisnąć Enter).

Zamiast tego możesz jawnie podać ścieżkę do folderu głównego Firebird, dla którego zostanie zainstalowana wtyczka szyfrowania:

[source,cmd]
----
install-Firebird-encryption-plugin.bat --crypt="C:\Firebird\5.0"
----

Następnie instalator wykona następujące kroki:

* *Automatyczne pobranie plików* +
Instalator pobiera potrzebne pliki (pliki dll, pliki konfiguracyjne i licencję próbną), a następnie zapisuje je w wybranym folderze Firebird.

* *Zmiana firebird.conf* +
Instalator zmienia `firebird.conf` — dodaje wiersz `KeyHolderPlugin = KeyHolder`

* *Ponowne uruchomienie Firebird (zachowaj ostrożność w środowisku produkcyjnym!)* +
Instalator uruchamia ponownie instancję Firebird. Na tym etapie Firebird jest gotowy do szyfrowania baz danych z użyciem licencji próbnej.

* *Tworzy foldery z plikami dla aplikacji klienckich* +
Instalator tworzy folder z plikami klienckimi w folderze, w którym go uruchomiono: `Client\32bit` i `Client\64bit`.
+
Tych plików można używać do tworzenia aplikacji, która będzie używać szyfrowania: skopiuj wszystkie pliki z tego folderu do folderu, w którym znajduje się plik wykonywalny twojej aplikacji. Bardzo ważne jest użycie dostarczonego pliku `fbclient.dll`.

=== Instalacja ręczna

W niektórych przypadkach instalacja skryptem nie jest możliwa, na przykład gdy Firebird działa na niestandardowym porcie. Wtedy można zainstalować wtyczkę szyfrowania ręcznie. W tym celu należy pobrać archiwum zip instalatora dla odpowiedniej wersji z jednego z adresów:

* https://cc.ib-aid.com/download/distr/crypt/CryptPlugin-FB_30_WINDOWS_64bit.zip
* https://cc.ib-aid.com/download/distr/crypt/CryptPlugin-FB_40_WINDOWS_64bit.zip
* https://cc.ib-aid.com/download/distr/crypt/CryptPlugin-FB_50_WINDOWS_64bit.zip

Wewnętrzna struktura archiwum wygląda tak:

│   ├── 32bit                    te same pliki dla 32 bitów
│   ├── 64bit

│   │   ├── fbcrypt.dll
│   │   ├── firebird.conf        KeyHolderPlugin = KeyHolder
│   │   ├── firebird.msg
│   │   ├── gbak.exe
│   │   ├── gfix.exe
│   │   ├── isql.exe
│   │   ├── nbackup.exe
│   │   ├── icudt63.dll, icudt63l.dat, icuin63.dll, icuuc63.dll
│   │   ├── libcrypto-1_1-x64.dll, libssl-1_1.dll
│   │   ├── msvcp140.dll, vcruntime140.dll, vcruntime140_1.dll
│   │   ├── key-plugins
│   │   │   ├── keyholderstdin.dll
│   │   │   └── KeySource.dll
│   │   └── plugins
│   │       ├── DbCrypt.conf

----

Jest to zawartość archiwum dla Firebird 5.0 z dnia 01.10.2026. Archiwum dla Firebird 3.0 zawiera inne biblioteki ICU (`icu*52`) i C++ (`msvcp100.dll`, `msvcr100.dll`).

Folder `Server` w archiwum zawiera pliki binarne *TYLKO* dla architektury x64. Zakłada się, że instalacja serwerowa ma właśnie taką architekturę, co prawie zawsze jest prawdą. Folder `Client` w archiwum zawiera pliki binarne zarówno dla architektury x86 (32bit), jak i x64 (64bit).

Pliki z folderu `Server` należy rozpakować do folderu głównego serwera Firebird. Część plików binarnych Firebird zostanie zastąpiona. Przed kopiowaniem zatrzymaj usługę Firebird.

Folder `Client` zawiera dwa podfoldery: `Client\32bit` i `Client\64bit`. Plików z tych folderów można używać do tworzenia aplikacji, która będzie używać szyfrowania: skopiuj wszystkie pliki z tego folderu do folderu, w którym znajduje się plik wykonywalny twojej aplikacji. Bardzo ważne jest użycie dostarczonego pliku `fbclient.dll`.

Folder `key-plugins` zawiera dwa źródła klucza. Właściwy plik skopiuj samodzielnie:

[cols="2,3,4", options="header"]
|===
| Plik | Gdzie skopiować | Przeznaczenie
| `KeySource.dll` | do folderu klienta, obok `fbclient.dll` | Biblioteka testowa z kluczami testowymi. Klucz otrzymują aplikacja i narzędzia bez przełączników. Patrz <<fbcrypt-keysource>>.
| `keyholderstdin.dll` | do folderu `plugins` klienta | Wtyczka `KeyHolderStdin`: narzędzie odczytuje klucz ze strumienia wejściowego. Patrz <<fbcrypt-utils-stdin>>.
|===

Bez skopiowania pliku narzędzie z przełącznikiem `-KeyHolder KeyHolderStdin` zgłasza `Key holder plugin KeyHolderStdin failed to load`.

W folderze `Client/db-crypt` znajdują się skrypt do sprawdzenia szyfrowania i testowa baza danych.

==== Konfiguracja

Po rozpakowaniu archiwum należy skonfigurować Firebird.

Aby włączyć wtyczkę szyfrowania bazy danych i przechowywania kluczy, należy podać nazwę wtyczki przechowywania kluczy w pliku konfiguracyjnym `firebird.conf`:

[source,conf]
----
KeyHolderPlugin = KeyHolder
----

Albo, zamiast tego, w pliku `databases.conf` podaj alias zaszyfrowanej bazy danych:

[source,conf]
----
myencrypted = C:\Temp\EMPLOYEE30\EMPLOYEE30.FDB
{
    KeyHolderPlugin = KeyHolder
}
----

W drugim przypadku łącz się z bazą danych przez alias (`localhost:myencrypted`).

Po zmianie konfiguracji uruchom ponownie usługę Firebird.

==== Testowanie

Po instalacji i konfiguracji można wykonać kilka testów, aby sprawdzić działanie szyfrowania i odszyfrowywania. Testy znajdują się w folderze `Client/db-crypt`.

[NOTE]
====
W archiwach z dnia 01.10.2026 zamiast plików `01-encrypt.bat` ... `05-gfix.bat` znajduje się jeden skrypt `run-tests.ps1`. Wykonuje on te same kroki dwa razy: z kluczem z biblioteki `KeySource.dll` i z kluczem ze strumienia wejściowego (wtyczka `KeyHolderStdin`). Przed każdym przebiegiem skrypt kopiuje właściwy plik z folderu `key-plugins` i zmienia parametr `KeyHolderPlugin` w pliku `firebird.conf` klienta. Polecenia, które wykonuje, opisano poniżej.
====

[WARNING]
====
Wszystkie testy są wykonywane z użyciem kluczy testowych. Jeśli w twojej instalacji klucze testowe znajdują się w pliku `%root%/plugins/KeyHolder.conf`, ten plik jest przeznaczony tylko do testów. Pamiętaj, aby zmienić jego nazwę lub go usunąć po zakończeniu testów.
====

== Linux

Skrypty do instalacji Firebird i wtyczki szyfrowania w systemie Linux znajdują się pod adresem https://github.com/IBSurgeon/firebirdlinuxinstall

Do instalacji w "czystych" (vanilla) wersjach Firebird służy jeden ze skryptów o nazwie `fb_vanilla-<version>.sh`. Na przykład dla Firebird 5.0 jest to plik https://raw.githubusercontent.com/IBSurgeon/firebirdlinuxinstall/refs/heads/main/fb_vanilla-50.sh[fb_vanilla-50.sh].

[source,bash]
----
wget https://raw.githubusercontent.com/IBSurgeon/firebirdlinuxinstall/refs/heads/main/fb_vanilla-50.sh
chmod +x fb_vanilla-50.sh
sudo ./fb_vanilla-50.sh
----

Zostanie wyświetlony następujący komunikat:

----
This program will install Firebird 5.0 on this computer
    Command line switches:
    --debug - also install debug information, takes more traffic;
    --crypt - install and configure crypto plugin
    --crypt-only[=/path/to/firebird] - install and configure ONLY crypto plugin without Firebird
Press Enter to start installation or ^C to abort
----

Przełącznik `--crypt` instaluje Firebird razem z wtyczką szyfrowania. Przełącznik `--crypt-only` instaluje tylko wtyczkę w już zainstalowanym Firebird:

[source,bash]
----
sudo ./fb_vanilla-50.sh --crypt-only=/opt/firebird
----

[NOTE]
====
Skrypt nie instaluje pakietu zgodności OpenSSL 1.1 i nie tworzy pliku z kluczami. Jeśli po działaniu skryptu szyfrowanie się nie uruchamia, wykonaj kroki instalacji ręcznej opisane poniżej.
====

=== Instalacja ręczna w systemie Linux

Poniższe kroki sprawdzono w systemie AlmaLinux 9 z Firebird 3.0, 4.0 i 5.0 zainstalowanymi w `/opt/firebird`. Wszystkie polecenia są wykonywane jako `root`.

Różnice między wersjami:

[cols="3,1,1,1", options="header"]
|===
| | FB 3.0 | FB 4.0 | FB 5.0
| Archiwum `CryptPlugin-FB_<V>_LINUX_64bit.tar.xz` | `30` | `40` | `50`
| Potrzebny OpenSSL 1.1 | tak | tak | nie (OpenSSL 3)
| Nazwa usługi systemd | `firebird-superserver` | `firebird` | `firebird`
| Zaszyfrowana kopia standardowym `gbak` | nie | tak | tak
| `MON$DATABASE.MON$CRYPT_STATE` | nie | tak | tak
|===

.Krok 1. Ustaw wersję
[source,bash]
----
V=50      # 30 = Firebird 3.0, 40 = Firebird 4.0, 50 = Firebird 5.0
FB=/opt/firebird
----

.Krok 2. Pobierz i rozpakuj archiwum
[source,bash]
----
cd /root
curl -LO https://cc.ib-aid.com/download/distr/crypt/CryptPlugin-FB_${V}_LINUX_64bit.tar.xz
mkdir -p /root/crypt
tar xJf CryptPlugin-FB_${V}_LINUX_64bit.tar.xz -C /root/crypt --strip-components=1
ls /root/crypt/Server/plugins
----

W folderze `Server/plugins` znajdują się pliki `libDbCrypt.so`, `libKeyHolder.so` i `DbCrypt.conf` (licencja próbna). Folder `Client` zawiera narzędzia i biblioteki klienckie.

.Krok 3. Zainstaluj OpenSSL 1.1 (tylko Firebird 3.0 i 4.0)
[source,bash]
----
dnf install -y compat-openssl11
ls /usr/lib64/libcrypto.so.1.1
----

Wtyczki dla Firebird 3.0 i 4.0 ładują `libcrypto.so.1.1`. Bez tej biblioteki instrukcja `ALTER DATABASE ENCRYPT` kończy się błędem `Library libcrypto.so.1.1 failed to load`. W systemach Debian i Ubuntu pakiet ma inną nazwę; zainstaluj pakiet, który zawiera `libcrypto.so.1.1`.

.Krok 4. Skopiuj pliki wtyczki
[source,bash]
----
cp /root/crypt/Server/plugins/* $FB/plugins/
ls -l $FB/plugins | grep -iE 'crypt|key'
----

.Krok 5. Utwórz plik z kluczem (do sprawdzenia)
[source,bash]
----
KEY=$(openssl rand -hex 32 | sed 's/../0x&,/g')
echo "Key=Red $KEY" > $FB/plugins/KeyHolder.conf
chown root:firebird $FB/plugins/KeyHolder.conf
chmod 640 $FB/plugins/KeyHolder.conf
----

Zapisz kopię klucza poza serwerem. Plik z kluczem na tym samym dysku co baza danych nadaje się tylko do sprawdzenia i programowania.

.Krok 6. Włącz wtyczkę przechowywania kluczy

Dla jednej bazy danych (`databases.conf`):

[source,bash]
----
cat >> $FB/databases.conf <<'EOF'

employee = /opt/firebird/examples/empbuild/employee.fdb
{
    KeyHolderPlugin = KeyHolder
}
EOF
----

Albo dla wszystkich baz danych (`firebird.conf`):

[source,bash]
----
echo "KeyHolderPlugin = KeyHolder" >> $FB/firebird.conf
----

Drugi wariant jest konieczny, jeśli odtwarzasz zaszyfrowaną kopię zapasową do nowego pliku.

.Krok 7. Uruchom ponownie Firebird
[source,bash]
----
# Firebird 3.0:
systemctl restart firebird-superserver
# Firebird 4.0 i 5.0:
systemctl restart firebird
----

.Krok 8. Zaszyfruj testową bazę danych
[source,bash]
----
$FB/bin/isql localhost:employee -user SYSDBA -password masterkey <<'EOF'
alter database encrypt with "DbCrypt" key Red;
commit;
show database;
EOF
----

W systemie Linux w nazwie wtyczki `"DbCrypt"` ma znaczenie wielkość liter. Nie usuwaj podwójnych cudzysłowów.

.Krok 9. Sprawdź wynik
[source,bash]
----
$FB/bin/gstat -h /opt/firebird/examples/empbuild/employee.fdb | grep -iE 'attrib|key name'
#   Attributes      force write, encrypted, plugin DbCrypt
#   Encryption key name:    RED
----

.Krok 10. Sprawdź, czy klucz jest wymagany
[source,bash]
----
mv $FB/plugins/KeyHolder.conf $FB/plugins/KeyHolder.conf.off
systemctl restart firebird            # firebird-superserver dla 3.0
echo "select count(*) from employee;" | $FB/bin/isql localhost:employee -user SYSDBA -password masterkey
#   Statement failed, SQLSTATE = 08006
#   Invalid crypt key RED
#   -Key not set
mv $FB/plugins/KeyHolder.conf.off $FB/plugins/KeyHolder.conf
systemctl restart firebird            # firebird-superserver dla 3.0
----

Tworzenie kopii zapasowych w systemie Linux opisano w <<fbcrypt-utils-gbak>>.

== Plik licencji

Wtyczka `DbCrypt` działa tylko z plikiem licencji `plugins/DbCrypt.conf`. Archiwa zawierają licencję próbną z ograniczonym okresem ważności. Dla systemu produkcyjnego zastąp plik licencją otrzymaną od IBSurgeon i uruchom ponownie Firebird.

Plik licencji jest potrzebny wszędzie, gdzie ładowana jest wtyczka `DbCrypt`: na serwerze i obok narzędzia `gbak`, które tworzy zaszyfrowane kopie zapasowe.

Parametry pliku opisano w <<fbcrypt-config-dbcrypt>>.
