[preface]
== Для кого это руководство

У вас есть приложение для Windows, которое работает с базой данных Firebird. Исходных кодов приложения нет, или менять их нельзя. Вы хотите зашифровать базу данных плагином шифрования IBSurgeon.

Приложение не меняется. Ключ шифрования передаёт небольшая библиотека `KeySource.dll`, которую вы кладёте рядом с клиентской библиотекой Firebird.

Руководство содержит готовый пример для Firebird 3.0, 4.0 и 5.0 на Windows x64. Начните с главы <<closed-gui-quick>>.

[TIP]
====
Основной текст короткий. Справочные сведения находятся в блоках «Подробности». В HTML и на GitHub блок раскрывается щелчком. В PDF все блоки раскрыты.
====

.Подробности: состав примера и что нужно для работы
[%collapsible]
====
Пример содержит:

* приложение `EmployeeApp` с таблицей данных. Оно играет роль приложения без исходных кодов;
* четыре варианта библиотеки `KeySource.dll`: ключ в коде, ключ в файле, ключ от программы в трее Windows, ключ от службы REST;
* скрипты, которые скачивают Firebird и плагин, ставят отдельный сервер и собирают каталоги рабочего места;
* автоматическую проверку всех сочетаний.

Что нужно для работы с примером:

* Windows 10 или новее, PowerShell 5.1;
* доступ в интернет к `github.com` и `cc.ib-aid.com`;
* Lazarus 4 с Free Pascal, если вы хотите собрать программы сами. Готовые программы можно скачать.

Общие сведения о плагине, генерации ключей, утилитах и параметрах находятся в основном руководстве: {mainguide}[Firebird Encryption plugin (PDF)]. Здесь оно называется «основное руководство».

Исходные тексты примера: {repo}/tree/main/examples/closed-gui[каталог `examples/closed-gui`].

== Задача: где находится ключ

Плагин `DbCrypt` шифрует страницы файла базы данных. Без ключа файл нельзя прочитать. Это защищает от кражи файла, диска, сервера и резервной копии диска.

Сервер без ключа не откроет базу данных. Кто-то должен дать ему ключ.

* Плохой путь: записать ключ в файл на сервере. Тот, кто украл сервер, получает базу данных и ключ вместе.
* Правильный путь: сервер ключа не хранит. Ключ приносит каждое подключение.

Приложение с исходными кодами приносит ключ вызовом библиотеки `fbcrypt`. Приложение без исходных кодов так не может. Для него ключ передаёт библиотека `KeySource.dll`.

[IMPORTANT]
====
Ключ всегда находится где-то на стороне рабочего места: в файле, в памяти программы, в голове человека, у службы ключей. Выбор варианта `KeySource` определяет, насколько трудно его оттуда достать. Ни один вариант не защищает от пользователя, у которого есть полный доступ к рабочему месту и право работать с базой данных.
====

.Подробности: чего шифрование не делает
[%collapsible]
====
* Пользователь, который подключился к базе данных с верным ключом и паролем, видит данные как обычно.
* Шифрование не заменяет права доступа SQL и пароли пользователей.
* Резервная копия `gbak` не шифруется сама. Её нужно шифровать отдельно, см. <<closed-gui-everyone>>.
====

== Как ключ попадает к базе данных

.Компоненты рабочего места и сервера
image::closed-gui/components.svg[pdfwidth=100%]

.Подробности: что делает каждый компонент
[%collapsible]
====
[cols="2,5", options="header"]
|===
| Компонент | Что делает
| Приложение | Вызывает обычные функции клиентской библиотеки Firebird. О шифровании не знает.
| `fbclient.dll` | Клиентская библиотека Firebird. Читает файл `firebird.conf` из своего каталога.
| `KeyHolder` клиента | Плагин `plugins\keyholder.dll`. Клиент загружает его, если в `firebird.conf` есть строка `KeyHolderPlugin = KeyHolder`.
| `KeySource.dll` | Ваша библиотека. Экспортирует одну функцию `MakeKeys`, которая возвращает ключи.
| `KeyHolder` сервера | Тот же плагин на сервере. Принимает ключ от клиента и передаёт его плагину `DbCrypt`.
| `DbCrypt` | Плагин шифрования `plugins\dbcrypt.dll`. Шифрует и расшифровывает страницы. Работает только с файлом лицензии `plugins\DbCrypt.conf`.
|===
====

=== Обычное подключение

Ключ запрашивает сервер. Клиентский плагин `KeyHolder` вызывает функцию `MakeKeys` библиотеки `KeySource.dll` и отправляет ключ серверу. Приложение ничего для этого не делает.

.Передача ключа при подключении к серверу
image::closed-gui/seq-remote.svg[pdfwidth=100%]

.Подробности: свойства этой схемы
[%collapsible]
====
* Клиент создаёт плагин `KeyHolder` заново для каждого подключения. Плагин каждый раз загружает `KeySource.dll` и один раз вызывает `MakeKeys`.
* От клиента к серверу ключ идёт в зашифрованном виде. Обмен защищён парами ключей, встроенными в плагины.
* Клиент отправляет серверу *все* ключи, которые вернула `MakeKeys`.
* Сервер не запоминает ключ для других подключений. Подключение без ключа получает ошибку, даже когда другой клиент в это время работает с базой данных.
====

=== Embedded

В режиме embedded сервера нет. Движок Firebird работает внутри приложения, и его плагин `KeyHolder` сам вызывает `MakeKeys`. Ключ не идёт по сети.

.Получение ключа в режиме embedded
image::closed-gui/seq-embedded.svg[pdfwidth=100%]

.Подробности: отличия от обычного подключения
[%collapsible]
====
* Плагин `DbCrypt` и файл лицензии `DbCrypt.conf` находятся в каталоге приложения.
* Режим embedded включает не приложение, а строка `Providers = Engine13` (для Firebird 3.0: `Engine12`) в файле `firebird.conf` рядом с `fbclient.dll`.
====

[[closed-gui-versions]]
== Отличия Firebird 3.0, 4.0 и 5.0

Библиотека `KeySource.dll` одинакова для всех трёх версий: один исходный текст, один файл. Отличается окружение.

[WARNING]
====
Firebird 3.0: официальная клиентская библиотека `fbclient.dll` не вызывает клиентский плагин `KeyHolder`. На рабочем месте должна быть библиотека `fbclient.dll` из архива плагина. Иначе `KeySource.dll` не используется, и подключение завершается ошибкой `Key not set`.
====

.Подробности: таблица отличий
[%collapsible]
====
[cols="3,2,2,2", options="header"]
|===
| Свойство | Firebird 3.0 | Firebird 4.0 | Firebird 5.0
| Архив плагина | `CryptPlugin-FB_30_…` | `CryptPlugin-FB_40_…` | `CryptPlugin-FB_50_…`
| Провайдер для embedded | `Engine12` | `Engine13` | `Engine13`
| `fbclient.dll` на рабочем месте | только из архива плагина | из архива плагина; официальный тоже работает | из архива плагина; официальный тоже работает
| Состояние шифрования в SQL | нет; смотрите `gstat -h` | `MON$CRYPT_STATE` | `MON$CRYPT_STATE`
| Ошибка без ключа, когда база открыта другим клиентом | `Missing correct crypt key` | `Missing database encryption key for your attachment` | то же
| Библиотеки ICU | `icu*52` | `icu*63` | `icu*63`
| Библиотеки C++ | `msvcp100`, `msvcr100` | `msvcp140`, `vcruntime140` | те же и `vcruntime140_1`
| Размер каталога embedded | 28 МБ | 53 МБ | 53 МБ
| Свой каталог `FIREBIRD_LOCK` рядом со службой Firebird той же версии | нужен | не нужен | не нужен
|===

Переключатели утилит `gbak`, `nbackup` и других тоже отличаются в 3.0. Они описаны в основном руководстве, глава «Поддержка в консольных утилитах Firebird».

== Быстрый старт

Команды выполняются в PowerShell. Права администратора не нужны. Установленные экземпляры Firebird не меняются.

[source,powershell]
----
git clone https://github.com/IBSurgeon/FirebirdEncryptionGuide
cd FirebirdEncryptionGuide\examples\closed-gui\deploy
Set-ExecutionPolicy -Scope Process Bypass
.\05-download-example.ps1
.\run-all.ps1 -Version 5
..\work\fb5\remote\EmployeeRemote.exe
----

В приложении нажмите btn:[Connect]. Оно показывает таблицу `CUSTOMER` из зашифрованной базы данных. В строке состояния написано `database: encrypted`.

.Приложение открыло зашифрованную базу данных на сервере
image::closed-gui/app-remote.png[pdfwidth=80%]

.Подробности: что делает каждая команда
[%collapsible]
====
[cols="3,5", options="header"]
|===
| Команда | Что делает
| `Set-ExecutionPolicy -Scope Process Bypass` | Разрешает запуск скриптов в этом окне PowerShell.
| `.\05-download-example.ps1` | Скачивает готовые программы примера. Если у вас есть Lazarus, пропустите этот шаг: программы соберёт скрипт `run-all.ps1 -LazarusDir D:\lazarus`.
| `.\run-all.ps1 -Version 5` | Скачивает Firebird 5.0 и архив плагина в `work\downloads`. Ставит сервер в `work\fb5\server`, порт 30055. Шифрует копию базы `employee` тестовым ключом `Red`. Собирает каталог рабочего места `work\fb5\remote` и каталог embedded `work\fb5\embedded` с библиотекой `KeySource.dll` варианта «а».
|===

[[closed-gui-quick-phrase]]
=== С парольной фразой

Базу данных можно зашифровать не ключом `0x…`, а парольной фразой. Фразу знает человек, на диске её нет.

[source,powershell]
----
.\run-all.ps1 -Version 5 -AskPassphrase
..\work\fb5\remote\EmployeeRemote.exe
----

Скрипт спрашивает фразу и шифрует ею базу данных. Рабочее место он собирает с вариантом «в»: при первом подключении программа в трее Windows спрашивает фразу и держит её в памяти.

.Окно поставщика ключа: введите парольную фразу
image::closed-gui/provider-ask.png[pdfwidth=60%]

Если сервер примера уже установлен, сначала выполните `.\cleanup.ps1 -Version 5`. Подробнее: <<closed-gui-encrypt>> и <<closed-gui-variant-c>>.

[WARNING]
====
Ключ `Red`, пароль `masterkey` и токен `test-token` в примере открыты всем. Не используйте их для настоящих данных.

Архив плагина содержит пробную лицензию. Она действует до конца текущего месяца. Для рабочей системы нужна постоянная лицензия IBSurgeon.

=== Сервер

Скрипт `10-install-server.ps1` делает то же, что нужно сделать на настоящем сервере: копирует плагин и лицензию в каталог Firebird и добавляет в `firebird.conf` строку:

[source,conf]
----
KeyHolderPlugin = KeyHolder
----

Файла `plugins\KeyHolder.conf` на сервере нет. Ключей сервер не хранит, поэтому файл не нужен.

.Подробности: шаги установки сервера
[%collapsible]
====
. Каталог `Server` из архива плагина копируется поверх каталога Firebird. В нём клиентская библиотека, `fbcrypt.dll`, OpenSSL, плагины `plugins\dbcrypt.dll` и `plugins\keyholder.dll`.
. Файл лицензии копируется в `plugins\DbCrypt.conf`.
. В конец файла `firebird.conf` добавляются строки:
+
[source,conf]
----
RemoteServicePort = 30055
IpcName = FB_CLOSED_GUI_5
KeyHolderPlugin = KeyHolder
----
+
Первые две строки нужны только примеру: они отделяют его сервер от других экземпляров Firebird на компьютере.

Файл `plugins\KeyHolder.conf` на сервере нужен только для параметров плагина, например `UnsafeClient` для клиентов Jaybird и .NET. Параметры описаны в основном руководстве, глава «Параметры конфигурации». Без файла плагин работает со значениями по умолчанию.
====

[[closed-gui-encrypt]]
=== Шифрование: ключ или парольная фраза

Скрипт `20-encrypt-database.ps1` шифрует копию базы `employee`. Сервер в это время остановлен. Есть два вида ключа:

[source,powershell]
----
# тестовый ключ Red: 32 байта в виде 0x..,0x..,
.\20-encrypt-database.ps1 -Version 5

# парольная фраза: скрипт спросит её, на экране она не видна
.\20-encrypt-database.ps1 -Version 5 -AskPassphrase

# парольная фраза в команде и своё имя ключа
.\20-encrypt-database.ps1 -Version 5 -KeyName Main -Passphrase "my long pass phrase 2026"
----

[cols="2,3,3", options="header"]
|===
| | Ключ `Key=<имя> 0x..,` | Фраза `Password=<имя> <фраза>`
| Что это | 16, 24 или 32 случайных байта | текст; плагин вычисляет из него ключ
| Кто его хранит | файл, библиотека, служба ключей | человек
| Подходит для | вариантов «а», «б», «г» | варианта «в» и параметра `Prompt`; работает и в «б», «г»
|===

Команда шифрования одна и та же: `ALTER DATABASE ENCRYPT WITH "DbCrypt" KEY <имя>`. Вид ключа определяет строка, которую получает плагин `KeyHolder`.

[WARNING]
====
Парольная фраза должна быть длинной: короткую фразу можно подобрать. В ней нельзя использовать символы `#`, `"`, `{`, `}` и сочетание `$(`. Пробелы в начале и в конце не допускаются. Скрипт это проверяет.
====

.Подробности: шаги скрипта и файл `db-key.conf`
[%collapsible]
====
. Копирует `employee.fdb` из примеров Firebird в `work\fb<N>\db\EMPLOYEE.FDB`.
. Создаёт временный файл `plugins\KeyHolder.conf` со строкой ключа: `Key=Red 0x..,` или `Password=Main my long pass phrase 2026`. Файл записывается в UTF-8 без BOM.
. Выполняет в `isql` команду `ALTER DATABASE ENCRYPT WITH "DbCrypt" KEY <имя>`.
. Ждёт, пока поле `MON$CRYPT_PAGE` вернётся к нулю. Шифрование идёт в фоне и только пока открыто подключение.
. Проверяет заголовок: `gstat -h` показывает `Attributes encrypted, plugin DbCrypt`.
. Удаляет файл `plugins\KeyHolder.conf`.
. Делает вторую копию зашифрованного файла для режима embedded.
. Записывает строку ключа в файл `work\fb<N>\db-key.conf`.

Файл `db-key.conf` нужен только примеру. Из него скрипты `40` и `41` берут имя ключа и строку ключа, чтобы настроить варианты `KeySource`. С настоящими данными такого файла рядом с сервером быть не должно: ключ или фраза хранятся только в вашем хранилище ключей.

Параметр `-Passphrase` оставляет фразу в истории команд PowerShell. Для настоящей фразы используйте `-AskPassphrase`.

Вариант «а» работает только с тестовым ключом `Red`: он записан в коде библиотеки. Если база данных зашифрована другим ключом или фразой, скрипты `40` и `41` с параметром `-KeySource a` завершаются с сообщением об этом.
====

.Подробности: как зашифровать свою базу данных
[%collapsible]
====
Способ 1, на сервере, как в скрипте:

. Остановите сервер или отключите пользователей.
. Создайте файл `plugins\KeyHolder.conf` с одной строкой: `Key=<имя> 0x..,` или `Password=<имя> <фраза>`.
. Подключитесь к базе данных и выполните `ALTER DATABASE ENCRYPT WITH "DbCrypt" KEY <имя>`. Не закрывайте подключение, пока шифрование не закончится.
. Удалите файл `plugins\KeyHolder.conf`.

Способ 2, с рабочего места, без файла на сервере. Выполните ту же команду в `isql` из каталога рабочего места. Ключ серверу передаст `KeySource.dll`:

[source,sql]
----
ALTER DATABASE ENCRYPT WITH "DbCrypt" KEY Main;
----

Способ 2 работает на Firebird 3.0, 4.0 и 5.0.

Генерация ключа, расшифровка и смена ключа описаны в основном руководстве, глава «Шифрование, расшифровка и смена ключа».
====

=== Каталог рабочего места

Скрипт `40-deploy-remote.ps1` собирает каталог `work\fb<N>\remote`: клиент Firebird из архива плагина, плагин `KeyHolder`, библиотеку `KeySource.dll` и приложение.

.Подробности: состав каталога
[%collapsible]
====
[source]
----
EmployeeRemote.exe      приложение
EmployeeApp.ini         параметры подключения приложения
fbclient.dll            клиентская библиотека из архива плагина
firebird.conf           две строки, см. ниже
firebird.msg
icu*.dll, icudt*.dat    библиотеки ICU
msvcp*.dll, vcruntime*  библиотеки C++
libcrypto-*.dll         OpenSSL
plugins\keyholder.dll   плагин KeyHolder
KeySource.dll           библиотека с ключом
KeySource.ini           настройки библиотеки
gbak.exe, isql.exe ...  утилиты из архива плагина
----

Плагин `DbCrypt` и лицензия рабочему месту не нужны.
====

Файл `firebird.conf` рабочего места:

[source,conf]
----
Providers = Remote
KeyHolderPlugin = KeyHolder
----

Строка `KeyHolderPlugin` включает передачу ключа. Без неё клиент плагин не загружает.

Строка `Providers = Remote` оставляет клиенту только сетевое подключение. Клиент не пытается загрузить движок embedded и его плагины и не ищет локальный сервер. Значение по умолчанию: `Remote,Engine13,Loopback`.

=== Каталог embedded

Скрипт `41-deploy-embedded.ps1` собирает каталог `work\fb<N>\embedded`. К файлам рабочего места добавляются движок Firebird, плагин `DbCrypt`, лицензия и файл базы данных.

.Подробности: состав каталога
[%collapsible]
====
[source]
----
EmployeeEmbedded.exe    приложение
plugins\engine13.dll    движок Firebird (engine12.dll для 3.0)
plugins\dbcrypt.dll     плагин шифрования
plugins\DbCrypt.conf    лицензия
intl\                   наборы символов
EMPLOYEE.FDB            зашифрованная база данных
----

База безопасности `security5.fdb` в этом каталоге не нужна.

Движок embedded и сервер не открывают один файл базы данных одновременно. Поэтому у каталога embedded своя копия базы.
====

Файл `firebird.conf`:

[source,conf]
----
Providers = Engine13
KeyHolderPlugin = KeyHolder
----

Строка `Providers = Engine13` (для Firebird 3.0: `Engine12`) оставляет только движок embedded: без сети и без локального сервера.

[[closed-gui-rules]]
== Правила для библиотеки KeySource

Эта глава нужна тому, кто пишет свою библиотеку. Чтобы запустить пример, её можно пропустить.

=== Функция MakeKeys

Библиотека экспортирует одну функцию с соглашением о вызовах `cdecl`:

[source,cpp]
----
char* MakeKeys(char* (*allocator)(unsigned int size), unsigned int* size);
----

* Память для текста ключей выделяйте только функцией `allocator`. Плагин сам её освобождает.
* В `size` запишите длину текста в байтах.
* Если вернуть `NULL`, подключение завершится ошибкой ключа.

.Подробности: объявление на Free Pascal, память, `NULL`
[%collapsible]
====
[source,pascal]
----
type
  TAllocator = function(size: Cardinal): PAnsiChar; cdecl;

function MakeKeys(Alloc: TAllocator; var Size: Cardinal): PAnsiChar; cdecl;
----

* Функция `allocator(n)` выделяет `n + 1` байт. Завершающий ноль ставит плагин.
* Если `MakeKeys` вернула `NULL`, плагин ищет ключи в файле `plugins\KeyHolder.conf` своего каталога. Если файла или ключей нет, подключение завершается ошибкой.
====

=== Текст ключей

`MakeKeys` возвращает текст: одна строка на ключ, строки разделяются символом перевода строки.

[source]
----
Key=Red 0xec,0xa1,0x52,0xf6,...,0x75,
Password=Main my long pass phrase 2026
----

* `Key=<имя> <байты>`: ключ в шестнадцатеричном виде, 16, 24 или 32 байта.
* `Password=<имя> <фраза>`: парольная фраза. Плагин вычисляет из неё ключ.

Имя ключа то же, что в команде `ALTER DATABASE ENCRYPT ... KEY <имя>`. Возвращайте только те ключи, которые нужны этому рабочему месту: клиент отправляет серверу все полученные ключи.

.Подробности: какие символы допустимы в парольной фразе
[%collapsible]
====
Плагин разбирает текст как файл конфигурации Firebird. В парольной фразе нельзя использовать символы `#`, `"`, `{`, `}` и сочетание `$(`. Пробелы в начале и в конце фразы удаляются. Фраза с такими символами даёт другой ключ или ошибку разбора.

Фигурные скобки опасны особо: с фразой `a {b} c` команда `ALTER DATABASE ENCRYPT` на Firebird 4.0 завершается без ошибки, а база данных остаётся незашифрованной. После шифрования всегда смотрите `gstat -h`: в строке `Attributes` должно быть слово `encrypted`.

Без изменений проходят: буквы, цифры, пробел внутри фразы, символы `'`, `;`, `=`, `\` и кириллица в UTF-8.
====

=== Четыре правила

.Жизнь библиотеки в процессе приложения
image::closed-gui/dll-life.svg[pdfwidth=100%]

. Закрепите библиотеку в процессе первой строкой `MakeKeys`. Иначе теряется память.
. Не создавайте потоков в библиотеке.
. Отказ должен быть быстрым. После отказа клиент вызывает `MakeKeys` ещё 5–9 раз.
. Не кладите `KeySource.dll` рабочего места в каталог сервера. Серверный `KeyHolder` тоже её вызовет.

.Подробности: как плагин вызывает библиотеку и как её закрепить
[%collapsible]
====
Плагин ведёт себя одинаково на Firebird 3.0, 4.0 и 5.0, при обычном подключении и в режиме embedded:

* `MakeKeys` вызывается один раз на каждое удачное подключение.
* Если `MakeKeys` вернула `NULL`, клиент вызывает её снова для того же подключения: 9 раз на Firebird 3.0 и 4.0, 5 раз на Firebird 5.0. Только потом приложение получает ошибку. В режиме embedded и при неверном ключе вызов один.
* Перед вызовом плагин загружает `KeySource.dll`, после вызова выгружает. Глобальные переменные библиотеки между вызовами не сохраняются.
* Выгрузка библиотеки, в которой работали несколько потоков, теряет память. Нагрузочная проверка (8 потоков, 1000 подключений, библиотека на Free Pascal) показала рост памяти процесса на 42 МБ. С закреплённой библиотекой рост 4,5 МБ, как у приложения с одним потоком.
* `MakeKeys` может вызываться из нескольких потоков одновременно.
* Внутри `MakeKeys` можно ждать. Ожидание 90 секунд не обрывает подключение.

Закрепление библиотеки. Так сделано во всех четырёх библиотеках примера:

[source,pascal]
----
GetModuleHandleExW(GET_MODULE_HANDLE_EX_FLAG_PIN or GET_MODULE_HANDLE_EX_FLAG_FROM_ADDRESS,
  @SomeFunctionOfTheLibrary, Module);
----

После этого вызова библиотека остаётся в процессе до его завершения. Память не теряется, глобальные переменные сохраняются. Поэтому вариант «г» может хранить кэш.

Быстрый отказ. Библиотека, которая ждёт сеть или пользователя, должна запомнить отказ на несколько секунд и на повторные вызовы сразу возвращать `NULL`. Иначе пользователь ждёт ошибку в 5–9 раз дольше и видит одно и то же окно несколько раз. Так сделано в вариантах «в» и «г».
====

=== Где плагин ищет библиотеку

Плагин загружает `KeySource.dll` по полному пути из каталога, где лежит `fbclient.dll`. Подменить библиотеку через переменную `PATH` нельзя.

[WARNING]
====
Если на рабочем месте задана переменная окружения `FIREBIRD`, клиент ищет `firebird.conf`, `plugins` и `KeySource.dll` в её каталоге. Ключ не находится. Удалите эту переменную.
====

.Подробности: общий модуль примера и сборка
[%collapsible]
====
Все библиотеки примера используют модуль `keysource\common\keysourcecommon.pas`:

[cols="2,5", options="header"]
|===
| Функция | Назначение
| `ReturnKeys` | Копирует текст ключей в память плагина. Пустой текст даёт `NULL`.
| `CleanKeys` | Оставляет только строки `Key=` и `Password=`. Убирает комментарии, пустые строки, BOM.
| `Setting` | Читает настройку из `KeySource.ini` рядом с библиотекой, секция `[KeySource]`.
| `LogLine` | Пишет строку в `KeySource.log`, если в настройках `Log=1`. Значение ключа в журнал не попадает.
| `PinLibrary` | Закрепляет библиотеку в процессе. Вызывается в начале каждой `MakeKeys`.
|===

Сборка одной библиотеки:

[source,cmd]
----
fpc -O2 -Fu..\common KeySource.lpr
----
====

== Четыре варианта KeySource

Скрипты `40-deploy-remote.ps1` и `41-deploy-embedded.ps1` принимают параметр `-KeySource` со значением `a`, `b`, `c` или `d`. Они кладут в каталог приложения нужную библиотеку и файл `KeySource.ini`.

[cols="1,3,3", options="header"]
|===
| Вариант | Где ключ | Команда
| «а» | в коде библиотеки | `.\40-deploy-remote.ps1 -Version 5 -KeySource a`
| «б» | в файле, например на съёмном диске | `.\40-deploy-remote.ps1 -Version 5 -KeySource b`
| «в» | в памяти программы в трее; его вводит человек | `.\40-deploy-remote.ps1 -Version 5 -KeySource c`
| «г» | у службы ключей в сети | `.\40-deploy-remote.ps1 -Version 5 -KeySource d`
|===

После команды запустите `..\work\fb5\remote\EmployeeRemote.exe`.

=== Вариант «а»: ключ в библиотеке

.Варианты «а» и «б»
image::closed-gui/variants-ab.svg[pdfwidth=100%]

Ключ записан константой в исходном тексте `keysource\a-static\KeySource.lpr`. Замените ключ `Red` своим и соберите библиотеку.

* Когда использовать: защита от кражи файла базы данных и резервных копий. Самый простой вариант.
* Риски: тот, кто скопировал `KeySource.dll`, может извлечь ключ. Ограничьте права на каталог приложения.

.Подробности: исходный текст
[%collapsible]
====
[source,pascal]
----
const
  Keys: AnsiString =
    'Key=Red 0xec,0xa1,0x52,0xf6,...,0xdc,0x75,'#10;

function MakeKeys(Alloc: TAllocator; var Size: Cardinal): PAnsiChar; cdecl;
begin
  PinLibrary;
  Result := ReturnKeys(Alloc, Keys, Size);
end;
----

В константу можно записать и строку `Password=<имя> <фраза>`. Скрипты примера ставят вариант «а» только для базы данных с ключом `Red`.
====

=== Вариант «б»: ключ в файле

Библиотека читает файл ключа при каждом подключении. Путь к файлу задан в `KeySource.ini`:

[source,ini]
----
[KeySource]
KeyFile=E:\keys\employee.key
----

* Когда использовать: ключ хранится отдельно от программы. Например, на съёмном диске, который пользователь уносит, или в папке с правами для группы пользователей.
* Риски: файл ключа можно скопировать. Когда диск вынут, новые подключения невозможны, но уже открытые продолжают работать.

.Подробности: формат файла и проверка
[%collapsible]
====
Исходный текст: `keysource\b-file\KeySource.lpr`.

Файл ключа имеет формат `KeyHolder.conf`, кодировка UTF-8. В нём строка ключа или строка парольной фразы:

[source]
----
Key=Red 0xec,0xa1,0x52,0xf6,...,0xdc,0x75,
----

В пути можно писать переменные окружения, например `%USERPROFILE%\keys\employee.key`. Без параметра `KeyFile` библиотека читает `KeySource.key` из своего каталога. Параметр `Log=1` включает журнал.

В примере роль съёмного диска играет каталог `work\fb5\keyfile`. Переименуйте его и нажмите btn:[Connect] ещё раз: приложение покажет ошибку ключа.
====

[[closed-gui-variant-c]]
=== Вариант «в»: поставщик ключа

Ключа на диске нет. Человек вводит парольную фразу или ключ один раз за сеанс работы. Его держит в памяти отдельная программа `KeyProvider.exe` в трее Windows.

.Запрос ключа у поставщика ключа
image::closed-gui/seq-provider.svg[pdfwidth=100%]

Как это выглядит:

. Пользователь запускает приложение и нажимает btn:[Connect].
. В трее Windows появляется значок поставщика ключа, на экране окно ввода.
. Пользователь вводит парольную фразу. Приложение подключается.
. При следующих подключениях окна нет: поставщик отдаёт ключ из памяти. Так же получают ключ другие приложения этого пользователя.

.Окно ввода ключа
image::closed-gui/provider-ask.png[pdfwidth=60%]

Что вводить в примере: фразу, которой вы зашифровали базу данных. Для базы с тестовым ключом `Red` вводится текст после имени ключа из файла `work\fb5\db-key.conf`: `0xec,0xa1,…,0x75,`.

* Когда использовать: ключ не должен лежать на диске рабочего места. Парольную фразу знает человек.
* Риски: ключ находится в памяти `KeyProvider.exe`, пока программа работает. Любая программа того же пользователя может запросить его. Короткую фразу можно подобрать.

.Подробности: окно поставщика, меню, неверный ввод
[%collapsible]
====
Библиотека: `keysource\c-provider\KeySource.lpr`. Поставщик ключа: `keyprovider\`.

.Окно поставщика ключа с журналом запросов
image::closed-gui/provider-window.png[pdfwidth=70%]

Меню значка в трее: показать окно, ввести ключ заново, забыть ключ, время хранения ключа (до выхода, 15 минут, 1 час), выход.

Поставщик сам определяет вид ввода. Текст вида `0x..,0x..,` длиной 16, 24 или 32 байта становится строкой `Key=<имя> …`. Любой другой текст становится строкой `Password=<имя> <фраза>` в UTF-8.

Если пользователь ввёл неверную фразу, сервер вернёт ошибку ключа. Выберите в меню «Forget the key» и подключитесь снова.

Если пользователь нажал btn:[Cancel], поставщик 15 секунд отвечает отказом без нового окна. Причина: клиент Firebird повторяет запрос ключа несколько раз.
====

.Подробности: настройки
[%collapsible]
====
Файл `KeySource.ini`:

[source,ini]
----
[KeySource]
ProviderExe=C:\Program Files\MyApp\keyprovider\KeyProvider.exe
TimeoutMs=120000
Log=0
----

[cols="1,4", options="header"]
|===
| Параметр | Значение
| `ProviderExe` | Полный путь к `KeyProvider.exe`. Библиотека запускает программу, если канал не найден, и проверяет, что канал принадлежит ей.
| `TimeoutMs` | Сколько ждать ответа. За это время пользователь вводит ключ.
| `Pipe` | Имя канала. По умолчанию `FbKeyProvider-<имя пользователя>`.
|===

Файл `KeyProvider.ini` рядом с `KeyProvider.exe`:

[source,ini]
----
[KeyProvider]
KeyName=Red
KeepMinutes=0
----

`KeyName` задаёт имя ключа: то же, что в команде `ALTER DATABASE ENCRYPT`. Скрипт `40` записывает сюда имя ключа базы данных примера. `KeepMinutes` задаёт время хранения; ноль означает «до выхода из программы».
====

.Подробности: протокол и защита канала
[%collapsible]
====
Именованный канал `\\.\pipe\FbKeyProvider-<имя пользователя>`. Один запрос на одно соединение. После ответа поставщик закрывает соединение.

[source]
----
запрос   GETKEYS 1 <номер процесса> <имя программы>\n
ответ    OK\n<строки Key=... или Password=...>
         ERROR <текст>\n
----

Защита канала:

* Список доступа канала разрешает доступ только текущему пользователю Windows.
* Подключения из сети запрещены (`PIPE_REJECT_REMOTE_CLIENTS`).
* Поставщик создаёт канал с флагом `FILE_FLAG_FIRST_PIPE_INSTANCE`. Если имя уже занято другой программой, он не запускается.
* Библиотека проверяет, что владелец канала есть программа из параметра `ProviderExe`.
* Библиотека открывает канал с уровнем `SECURITY_IDENTIFICATION`. Программа на другом конце канала не может действовать от имени приложения.
* Номер процесса клиента поставщик берёт у Windows, а не из текста запроса.
====

=== Вариант «г»: служба ключей REST

Ключ выдаёт служба в сети. Рабочее место хранит только адрес службы и токен доступа.

.Запрос ключа у службы REST
image::closed-gui/seq-rest.svg[pdfwidth=100%]

Проверка. В первом окне PowerShell запустите демо-сервер ключей:

[source,powershell]
----
..\restserver\key-server.ps1 -KeysFile ..\work\fb5\db-key.conf
----

Во втором окне:

[source,powershell]
----
.\40-deploy-remote.ps1 -Version 5 -KeySource d
..\work\fb5\remote\EmployeeRemote.exe
----

* Когда использовать: много рабочих мест, нужен центральный контроль. Доступ рабочего места можно закрыть без замены ключа базы данных.
* Риски: без сети новые подключения невозможны. Токен на рабочем месте нужно защищать так же, как ключ: с токеном можно получить ключ.

.Подробности: настройки
[%collapsible]
====
Библиотека: `keysource\d-rest\KeySource.lpr`. Она использует WinHTTP, часть Windows. Другие dll не нужны.

Файл `KeySource.ini`:

[source,ini]
----
[KeySource]
Url=https://keys.example.com/keys/Red
TokenFile=%USERPROFILE%\keys\token.txt
TimeoutMs=5000
CacheSeconds=300
RetrySeconds=10
Log=0
----

[cols="1,4", options="header"]
|===
| Параметр | Значение
| `Url` | Адрес запроса. С `https` сертификат сервера проверяет Windows.
| `Token` | Токен доступа в самом файле настроек. Только для проверки.
| `TokenFile` | Файл с токеном. Ограничьте права на этот файл.
| `TimeoutMs` | Предел времени запроса.
| `CacheSeconds` | Сколько секунд ключ хранится в памяти процесса. Ноль: запрос при каждом подключении.
| `RetrySeconds` | После неудачного запроса библиотека столько секунд не обращается к службе. По умолчанию 10.
|===
====

.Подробности: запрос, ответ и кэш
[%collapsible]
====
[source,http]
----
GET /keys/Red HTTP/1.1
Authorization: Bearer <токен>
X-Workstation: <компьютер>\<пользователь>
----

Ответ с кодом 200 содержит текст ключей: строку `Key=<имя> 0x..,` или `Password=<имя> <фраза>`. Любой другой код библиотека считает отказом и возвращает `NULL`.

Кэш. Одно подключение к Firebird занимает 65–120 мс. Запрос REST при каждом подключении добавил бы своё время и нагрузку на службу. Поэтому после первого удачного ответа библиотека хранит ключ в памяти `CacheSeconds` секунд. Кэш сохраняется между подключениями, потому что библиотека закреплена в процессе. За 1000 подключений одного процесса служба получает один запрос.

Неудачный запрос библиотека тоже запоминает, на `RetrySeconds` секунд. Без этого при остановленной службе ошибка появлялась через 37 секунд; с этим через 5 секунд.
====

.Подробности: демо-сервер и требования к настоящей службе
[%collapsible]
====
Скрипт `restserver\key-server.ps1` нужен только для проверки примера. Адрес `http://localhost:8085`, токен `test-token`. Параметр `-KeysFile` задаёт файл ключей; без него служба выдаёт тестовые ключи из `examples\common\test-keys.conf`. Каждый запрос пишется в окно и в журнал.

Остановите демо-сервер и запустите приложение заново: оно покажет ошибку ключа.

Требования к настоящей службе ключей:

* Только HTTPS.
* Свой токен для каждого рабочего места. Токен можно отозвать.
* Журнал всех запросов: время, рабочее место, имя ключа, результат.
* Ключи в службе хранятся в защищённом хранилище.
* Служба отдаёт рабочему месту только его ключи.
====

== Способ без библиотеки: параметр Prompt

Плагин `KeyHolder` умеет сам спросить ключ или парольную фразу у пользователя. Библиотека `KeySource.dll` для этого не нужна. В каталоге рабочего места создайте файл `plugins\KeyHolder.conf`:

[source,conf]
----
Prompt = Enter key %k for database %d
----

.Окно ввода ключа плагина KeyHolder
image::closed-gui/prompt.png[pdfwidth=60%]

Способ работает только для обычного подключения. Для embedded используйте `KeySource.dll`.

.Подробности: как это работает и чем отличается от варианта «в»
[%collapsible]
====
`%k` заменяется именем ключа, `%d` именем базы данных.

. Приложение подключается. Ключа нет, сервер возвращает ошибку ключа.
. Клиентский `KeyHolder` показывает окно ввода.
. Пользователь вводит ключ `0x..,` или парольную фразу. Клиент повторяет подключение.
. После удачного подключения ключ хранится в памяти приложения до его завершения.

Окно появляется при обычном подключении: в утилите `isql` (Firebird 3.0, 4.0, 5.0) и в приложении примера (Firebird 5.0). В режиме embedded с настройкой `Providers = Engine13` окна нет: ни в `isql`, ни в приложении примера.

[cols="2,3,3", options="header"]
|===
| | `Prompt` | Вариант «в»
| Что нужно установить | одну строку в `KeyHolder.conf` | `KeySource.dll` и `KeyProvider.exe`
| Где хранится ключ | в памяти каждого приложения | в памяти одной программы
| Несколько приложений | каждое спрашивает ключ | ключ вводится один раз
| Время хранения, «забыть ключ» | нет | есть
| Своя логика (смарт-карта, проверка) | нет | можно дописать
|===
====

== Сравнение вариантов

.Где находится ключ
image::closed-gui/key-location.svg[pdfwidth=100%]

Как выбрать:

* Нужно быстро закрыть риск кражи файла базы данных: вариант «а».
* Ключ должен уходить с рабочего места вместе с человеком: вариант «б» со съёмным диском или вариант «в» с парольной фразой.
* Ключа не должно быть на диске: вариант «в» или `Prompt`.
* Много рабочих мест и нужен отзыв доступа: вариант «г».

.Подробности: таблица сравнения
[%collapsible]
====
[cols="2,2,3,3", options="header"]
|===
| Вариант | Сложность | Защищает от | Не защищает от
| «а» ключ в библиотеке | очень простая | кражи файла базы данных, сервера, резервных копий | копирования каталога приложения
| «б» ключ в файле | простая | того же; кражи рабочего места без съёмного диска | копирования файла ключа
| «в» поставщик ключа | средняя | того же; кражи рабочего места; ключа нет на диске | программ того же пользователя, пока ключ в памяти
| «г» служба REST | высокая: нужна служба | того же; рабочее место можно отключить | кражи токена, пока его не отозвали
| `Prompt` | очень простая | того же, что «в» | неудобно: ключ вводится в каждом приложении
|===

Варианты можно развивать. Модуль `keysourcecommon.pas` и четыре примера дают основу для своей библиотеки: ключ со смарт-карты, из хранилища Windows, от службы каталогов.

[[closed-gui-everyone]]
== Ключ нужен каждому подключению

Сервер не делится ключом между подключениями. Ключ нужен всем, кто подключается к базе данных: рабочим местам, администратору с `isql`, заданиям резервного копирования, программам обмена данными и отчётов.

Утилиты из каталога рабочего места получают ключ так же, как приложение: через ту же `fbclient.dll` и ту же `KeySource.dll`.

[source,cmd]
----
isql -user SYSDBA -password masterkey localhost/30055:crypt_employee
gbak -b -user SYSDBA -password masterkey localhost/30055:crypt_employee D:\backup\emp.fbk
----

[WARNING]
====
Файл резервной копии из второй команды *не зашифрован*. Утилита `gbak` шифрует резервную копию только с переключателем `-KEYHOLDER` (Firebird 4.0 и 5.0) или `-KEYFILE` (Firebird 3.0). См. основное руководство, глава «Поддержка в консольных утилитах Firebird».
====

.Подробности: задания на сервере
[%collapsible]
====
Задание резервного копирования на сервере не должно брать ключ из файла на том же диске, где лежит база данных. Варианты описаны в основном руководстве: плагин `KeyHolderStdin`, который получает ключ из стандартного ввода, и зашифрованные резервные копии.

Клиент без ключа получает ошибку, даже когда другой клиент в это время работает с базой данных.
====

== Перенос на своё приложение

Список проверки:

. *Разрядность.* Клиентские файлы и `KeySource.dll` той же разрядности, что приложение.
. *Клиентская библиотека.* Замените `fbclient.dll` или `gds32.dll` приложения библиотекой из архива плагина.
. *Файлы рядом с ней.* Все файлы каталога `Client\64bit`, `plugins\keyholder.dll`, ваша `KeySource.dll` и `firebird.conf` со строкой `KeyHolderPlugin = KeyHolder`.
. *Версия.* Архив плагина той же версии, что сервер: 3.0, 4.0 или 5.0.
. *Переменная `FIREBIRD`.* На рабочем месте её быть не должно.
. *Embedded.* Добавьте `plugins\dbcrypt.dll` и лицензию `plugins\DbCrypt.conf`.
. *Сервер.* Строка `KeyHolderPlugin = KeyHolder` в `firebird.conf`, плагины и лицензия в `plugins`. Ключей на сервере нет: ни файла `plugins\KeyHolder.conf` с ключами, ни `KeySource.dll`.
. *Проверка.* Поставьте диагностическую библиотеку: `.\40-deploy-remote.ps1 -Version 5 -KeySource probe`.
. *Обновление.* Сервер и рабочие места обновляйте из одного архива плагина.

.Подробности к пунктам списка
[%collapsible]
====
* *Разрядность.* Важна разрядность приложения, а не Windows. Для 32-битного приложения берите каталог `Client\32bit` из архива плагина и соберите `KeySource.dll` 32-битным компилятором. Программы примера собраны только для 64 бит.
* *Клиентская библиотека.* Найдите файл, который использует приложение. Обычно он лежит рядом с exe-файлом. Если приложение ищет `gds32.dll`, скопируйте `fbclient.dll` под этим именем. Если приложение загружает библиотеку из каталога `System32`, рядом с ней нет ни `plugins`, ни `KeySource.dll`: положите клиентские файлы в каталог приложения.
* *Проверка.* Диагностическая библиотека `keysource\probe` возвращает ключ базы данных и пишет в `KeySource.log` каждую загрузку и каждый вызов. Если журнал пуст, приложение использует другую клиентскую библиотеку или другой `firebird.conf`.
====

.Подробности: Firebird 3.0 рядом со службой Firebird 3.0
[%collapsible]
====
Отдельный сервер Firebird 3.0, запущенный как программа, не открывает базу данных, если на том же компьютере работает служба Firebird 3.0. В `firebird.log` появляется сообщение:

[source]
----
MappingIpc: Cannot initialize the shared memory region
----

Решение: задать серверу свой каталог блокировок в переменной окружения `FIREBIRD_LOCK`. Скрипты примера делают это сами. Приложение embedded должно использовать тот же каталог, когда работает одновременно с таким сервером. Для этого скрипт `41` создаёт файл запуска `EmployeeEmbedded.cmd`.

Для Firebird 4.0 и 5.0 переменную `FIREBIRD_LOCK` задавать не нужно.
====

== Смена ключа, потеря ключа, резервные копии

* *Смена ключа.* Firebird не меняет ключ одной командой. Нужно расшифровать базу данных и зашифровать новым ключом, или восстановить резервную копию с новым ключом. Давайте новому ключу новое имя.
* *Потеря ключа.* Без ключа или парольной фразы база данных и зашифрованные резервные копии не читаются. Восстановить их нельзя. Храните копию отдельно от базы данных и от рабочих мест: в сейфе, у двух ответственных людей.
* *Резервные копии.* Незашифрованная резервная копия рядом с зашифрованной базой данных отменяет всю защиту.

.Подробности: что делать на рабочих местах после смены ключа
[%collapsible]
====
* вариант «а»: соберите и раздайте новую `KeySource.dll`;
* вариант «б»: замените файл ключа;
* вариант «в»: пользователи вводят новую фразу; в `KeyProvider.ini` запишите новое имя ключа;
* вариант «г»: замените ключ в службе ключей. Рабочие места получат его после истечения `CacheSeconds` или после перезапуска приложения.

В вариантах «а», «б» и «г» библиотека может некоторое время возвращать оба ключа: старый и новый.

Проверьте, чем зашифрована каждая резервная копия и где лежит её ключ.

Основное руководство: главы «Шифрование, расшифровка и смена ключа» и «Поддержка в консольных утилитах Firebird».
====

== Диагностика

. Включите журнал библиотеки: строка `Log=1` в `KeySource.ini`. Журнал `KeySource.log` появляется рядом с библиотекой. В примере журнал включён.
. Журнала нет: клиент не вызывает библиотеку. Проверьте строку `KeyHolderPlugin = KeyHolder` в `firebird.conf` рядом с `fbclient.dll`, переменную `FIREBIRD` и версию `fbclient.dll` (для 3.0 только из архива плагина).
. Журнал есть: найдите сообщение в таблицах ниже.

.Подробности: сообщения об ошибках Firebird и плагина
[%collapsible]
====
[cols="3,4,4", options="header"]
|===
| Сообщение | Причина | Что сделать
| `Invalid crypt key RED` +
`Key not set`
| Сервер не получил ключ. Библиотека не найдена, вернула `NULL`, или клиент не загрузил `KeyHolder`.
| Проверьте `KeySource.log`. Если журнала нет, см. шаг 2.

| `Invalid crypt key RED` без строки `Key not set`
| Ключ с именем `RED` получен, но его значение неверно.
| Проверьте значение ключа или парольную фразу.

| `Missing database encryption key for your attachment` +
`Missing correct crypt key`
| То же, что `Key not set`, но база данных уже открыта другим подключением.
| Те же действия.

| `Bad key or password passed from external source`
| `MakeKeys` вернула строку неверного формата: нет значения после имени ключа.
| Исправьте текст ключей. Формат: `Key=<имя> <значение>`.

| `Unknown key name … - key can't be found in external source`
| `MakeKeys` вернула ключи, но ключа с нужным именем среди них нет.
| Проверьте имя ключа: `gstat -h` показывает его в строке `Encryption key name`.

| `text stream: illegal line`
| В тексте ключей есть символ, который ломает разбор, например кавычка.
| Уберите символы `#`, `"`, `{`, `}`, `$(` из парольной фразы.

| `License is incorrect`, ошибки лицензии
| Нет файла `plugins\DbCrypt.conf`, или лицензия не для этой версии, или срок истёк.
| Проверьте лицензию. Пробная лицензия из архива действует до конца месяца.

| `MappingIpc: Cannot initialize the shared memory region` в `firebird.log`
| Firebird 3.0: работает другая служба Firebird 3.0.
| Задайте серверу свой `FIREBIRD_LOCK`.

| `Wrong file for memory mapping`
| Два экземпляра Firebird одной версии используют разные каталоги `FIREBIRD_LOCK` в одном сеансе Windows.
| Задайте им один каталог или остановите один из них.

| `can't format message … firebird.msg not found`
| Клиент ищет свои файлы не там. Обычно задана переменная `FIREBIRD`.
| Удалите переменную `FIREBIRD`.
|===

Общие ошибки плагина описаны в основном руководстве, глава «Диагностика ошибок».
====

.Подробности: сообщения в `KeySource.log`
[%collapsible]
====
[cols="4,5", options="header"]
|===
| Сообщение | Значение
| `cannot read the file of keys …, error N` | Вариант «б»: файла нет или нет прав. `N` есть код ошибки Windows.
| `no lines "Key=" or "Password=" in the file` | Вариант «б»: файл прочитан, но ключей в нём нет.
| `the key provider is not running` | Вариант «в»: канал не найден, параметр `ProviderExe` не задан.
| `cannot start the key provider` | Вариант «в»: неверный путь в `ProviderExe`.
| `the pipe does not belong to the key provider from the settings` | Вариант «в»: имя канала занято другой программой.
| `the key provider answered: ERROR the user did not enter the key` | Вариант «в»: пользователь закрыл окно ввода.
| `the key service does not answer, error N` | Вариант «г»: нет сети, неверный адрес, служба остановлена.
| `the last request failed a moment ago; no new request` | Вариант «г»: повторный вызов в течение `RetrySeconds` после отказа.
| `the key service answered with the status 401` | Вариант «г»: неверный токен.
|===
