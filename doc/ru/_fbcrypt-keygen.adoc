[[fbcrypt-keygen]]
= Генерация ключа

Для генерации ключей, которые могут быть использованы для шифрования, мы разработали утилиту `aesKeyGen`, которая генерирует ключи для использования в алгоритме шифрования AES256. Использование утилиты тривиально

[source,cmd]
----
aesKeyGen.exe
----

для Linux команда выглядит следующим образом:

[source,bash]
----
./aesKeyGen
----

Вывод утилиты будет таким:

[listing]
----
const unsigned char aes256[] = {
0xd6,0xd8,0x8d,0x07,0x09,0x70,0xfe,0x8c,0x2e,0xfd,0xa2,0xee,0xcd,0x84,0xab,0xd3,0x89,0x48,0x29,0xa1,0x2b,0xf0,0xb9,0x81,0x65,0x2c,0xb2,0x92,0xad,0x22,0xb6,0xe1,
};
----

Утилита получает 32 случайных байта от криптографического генератора библиотеки OpenSSL. Каждый запуск даёт новый ключ.

Если утилиты `aesKeyGen` нет под рукой, ключ в том же формате можно получить с помощью `openssl`:

[source,bash]
----
openssl rand -hex 32 | sed 's/../0x&,/g'
----

[IMPORTANT]
====
Сохраните копию ключа в надёжном месте *вне* сервера базы данных. Потерянный ключ восстановить нельзя: данные в базе данных и в зашифрованных резервных копиях будут недоступны.
====

[[fbcrypt-keygen-format]]
== Формат ключа

Текстовая запись ключа используется в файле `KeyHolder.conf`, в библиотеке `KeySource`, во входном потоке плагина `KeyHolderStdin` и в свойствах подключения Java и .NET.

[source]
----
<key_value> ::= 0x<hex-pair>,[0x<hex-pair>,...]
----

Правила:

* Каждый байт записывается ровно пятью символами: `0x`, две шестнадцатеричные цифры и запятая.
* Пробелы между байтами не допускаются.
* Запятая после последнего байта допускается. Утилита `aesKeyGen` выводит ключ с такой запятой, удалять её не нужно.
* Длина ключа -- 16, 24 или 32 байта (AES-128, AES-192, AES-256). Ключ другой длины вызовет ошибку `Invalid key length`.
* Имя ключа не содержит пробелов. Регистр букв в имени не учитывается.

== Как использовать данный ключ?

=== В файле `KeyHolder.conf`

Этот файл может использоваться только для целей отладки.

Формат сохранения ключа следующий:

[source,cmd]
----
Key=<KeyName> <key_value>

<key_value> ::= 0x<hex-pair>,[0x<hex-pair>,...]
----

У каждого ключа есть имя, которое записывается после `Key=`. Далее после пробела следует сам ключ. Файл может содержать несколько строк `Key=`.

Пример:

[source,conf]
----
Key=Red 0xec,0xa1,0x52,0xf6,0x4d,0x27,0xda,0x93,0x53,0xe5,0x48,0x86,0xb9,0x7d,0xe2,0x8f,0x3b,0xfa,0xb7,0x91,0x22,0x5b,0x59,0x15,0x82,0x35,0xf5,0x30,0x1f,0x04,0xdc,0x75,
----

На Linux ограничьте доступ к файлу:

[source,bash]
----
chown root:firebird /opt/firebird/plugins/KeyHolder.conf
chmod 640 /opt/firebird/plugins/KeyHolder.conf
----

[[fbcrypt-keygen-password]]
=== Парольная фраза вместо ключа

Вместо двоичного ключа можно задать парольную фразу. Для этого используется параметр `Password`:

[source,conf]
----
Password=<KeyName> <passphrase>
----

Плагин вычисляет из фразы ключ длиной 32 байта функцией PBKDF2 (HMAC-SHA256, 10000 итераций). Одна и та же фраза всегда даёт один и тот же ключ.

Строку `Password=` можно использовать там же, где и строку `Key=`: в файле `KeyHolder.conf`, в библиотеке `KeySource` и во входном потоке плагина `KeyHolderStdin`.

Плагин читает строку как файл конфигурации Firebird. Поэтому не все символы допустимы во фразе:

[cols="2,5", options="header"]
|===
| Символ | Что происходит
| `"` | Строка не разбирается. Ошибка `illegal line`.
| `#` | Плагин получает другую фразу. Ключ не подходит: `Invalid crypt key`.
| `{` и `}` | Плагин не получает ключ. Из библиотеки `KeySource`: ошибка `Invalid crypt key`. Из файла `KeyHolder.conf`: оператор `ALTER DATABASE ENCRYPT` завершается без ошибки, но база данных остаётся незашифрованной.
| `$(` | Начало подстановки. Плагин получает другую фразу или не разбирает строку.
| пробелы в начале и в конце | Удаляются.
|===

Без изменений проходят буквы, цифры, пробелы внутри фразы, символы `'`, `;`, `=`, `\` и буквы национальных алфавитов. Файл с такой фразой сохраняйте в кодировке UTF-8 без BOM.

[NOTE]
====
Стойкость такого ключа равна стойкости фразы. Случайный ключ из 32 байт надёжнее. Используйте длинную фразу, если выбираете этот способ.
====

=== В утилитах командной строки с плагином KeyHolderStdin

Общий формат вызова утилит командной строки с плагином `KeyHolderStdin` следующий (Firebird 4.0 и 5.0; для версии 3.0 см. <<fbcrypt-utils-fb3>>):

[source,cmd]
----
echo Key=<KeyName> <key_value> | <utils> -KeyHolder KeyHolderStdin ...

<key_value> ::= 0x<hex-pair>,[0x<hex-pair>,...]
----

Подробнее см. <<fbcrypt-utils>>.

=== В приложении на С/С++

Сгенерированный ключ можно взять как есть, удалив завершающую запятую.

[source,cpp]
----
const unsigned char aes256[] = {
0xd6,0xd8,0x8d,0x07,0x09,0x70,0xfe,0x8c,0x2e,0xfd,0xa2,0xee,0xcd,0x84,0xab,0xd3,0x89,0x48,0x29,0xa1,0x2b,0xf0,0xb9,0x81,0x65,0x2c,0xb2,0x92,0xad,0x22,0xb6,0xe1
};
----

=== В приложении на Delphi и Lazarus

Здесь всё достаточно просто, достаточно заменить все символы ключа `0x` на `$` и удалить завершающую запятую.

[source,delphi]
----
const keyRed: array [0..31] of byte  = ($d6,$d8,$8d,$07,$09,$70,$fe,$8c,$2e,$fd,$a2,$ee,$cd,$84,$ab,$d3,$89,$48,$29,$a1,$2b,$f0,$b9,$81,$65,$2c,$b2,$92,$ad,$22,$b6,$e1);
----

=== В приложении на Java и .NET

Драйверы Jaybird и Firebird .NET получают ключ в текстовом виде. Имя ключа и значение записываются через двоеточие:

[source]
----
MyKey:0xd6,0xd8,0x8d,0x07,0x09,0x70,0xfe,0x8c,0x2e,0xfd,0xa2,0xee,0xcd,0x84,0xab,0xd3,0x89,0x48,0x29,0xa1,0x2b,0xf0,0xb9,0x81,0x65,0x2c,0xb2,0x92,0xad,0x22,0xb6,0xe1,
----

Подробнее см. <<fbcrypt-client-java>> и <<fbcrypt-client-net>>.

[[fbcrypt-keygen-clientkeys]]
== Индивидуальные ключи клиентов

В некоторых системах один и тот же ключ базы данных получают многие клиенты (филиалы, рабочие станции, партнёры). Утилита `ClientKeygen` позволяет выдать каждому клиенту собственный ключ и видеть в журнале сервера, с каким ключом выполнено подключение.

[NOTE]
====
Индивидуальные ключи клиентов поддерживает только плагин для Firebird 5.0 (HQbird 5). В версиях для Firebird 3.0 и 4.0 этой возможности нет. Утилита `ClientKeygen` входит не во все пакеты. Если её нет в вашем пакете, обратитесь в поддержку IBSurgeon.
====

=== Как это работает

. Утилита `ClientKeygen` берёт ключ базы данных и создаёт клиентский ключ длиной 64 байта. Клиентский ключ содержит случайные данные, номер ключа и ключ базы данных. Утилита шифрует его значением параметра `License` из файла `DbCrypt.conf`.
. Клиент передаёт серверу клиентский ключ вместо ключа базы данных. Имя ключа остаётся прежним.
. Плагин `DbCrypt` на сервере расшифровывает клиентский ключ своей лицензией. Он получает ключ базы данных и номер клиентского ключа.

Из этого следует:

* Заново шифровать базу данных не нужно. Все клиентские ключи открывают одну и ту же базу данных.
* Клиентский ключ работает только на сервере с тем же значением `License`, которое было у утилиты `ClientKeygen`.
* Ключ базы данных должен иметь длину 32 байта.
* Обычный ключ базы данных продолжает работать. Храните его только у администратора.

=== Создание ключей

Синтаксис:

[source]
----
ClientKeygen {keyname} {keycount} [starting]
----

[cols="1,3", options="header"]
|===
| Параметр | Значение
| `keyname` | имя ключа базы данных в файле `KeyHolder.conf`
| `keycount` | сколько клиентских ключей создать
| `starting` | номер первого ключа (по умолчанию `1`)
|===

Утилита читает ключ базы данных из файла `KeyHolder.conf` и лицензию из файла `DbCrypt.conf`. Оба файла должны находиться в текущем каталоге или в каталоге `../plugins`. Результат утилита записывает в текущий каталог.

Порядок действий:

. На компьютере администратора создайте пустой каталог.
. Скопируйте в него файл `DbCrypt.conf` сервера.
. Создайте в нём файл `KeyHolder.conf` со строкой `Key=<имя> <значение>` для ключа базы данных.
. Запустите утилиту в этом каталоге:
+
[source,bash]
----
ClientKeygen Red 20 1
----
+
Утилита создаст 20 файлов: `KeyHolder.conf.1`, `KeyHolder.conf.2`, ... `KeyHolder.conf.20`. Каждый файл содержит одну строку `Key=Red <key_value>` со значением длиной 64 байта.
. Передайте каждому клиенту его файл по защищённому каналу. Запишите, какой номер ключа получил каждый клиент.
. Удалите каталог. В нём находится ключ базы данных.

Чтобы позже добавить клиентов, запустите утилиту с третьим параметром. Например, `ClientKeygen Red 5 21` создаст ключи с номерами от 21 до 25.

=== Использование на клиенте

Клиентский ключ используется так же, как обычный ключ. Имя ключа то же, длина значения 64 байта.

[cols="2,4", options="header"]
|===
| Способ передачи ключа | Что сделать
| Библиотека `fbcrypt`
| Передайте значение в `fbcrypt_key` с длиной 64.

| Клиентский плагин `KeyHolder`
| Сохраните файл `KeyHolder.conf.<номер>` под именем `plugins/KeyHolder.conf` в каталоге клиентской библиотеки. В клиентском `firebird.conf` укажите `KeyHolderPlugin = KeyHolder`.

| Библиотека `KeySource`
| Верните строку из файла в функции `MakeKeys`.

| Плагин `KeyHolderStdin`
| Передайте строку из файла во входной поток утилиты.

| Свойство драйвера (Jaybird, .NET)
| Используйте значение в записи `<имя>:0x..,0x..,`. Нужен параметр `UnsafeClient = true`.
|===

=== Журнал подключений

Чтобы сервер записывал в `firebird.log`, какой клиентский ключ использован, добавьте в файл `plugins/DbCrypt.conf` сервера параметр и перезапустите Firebird:

[source,conf]
----
Logger = true
----

Сообщение в журнале выглядит так:

[listing]
----
DbCrypt login from 192.168.1.15/54907 using key 7
----

Здесь `192.168.1.15/54907` -- адрес и порт клиента, `7` -- номер клиентского ключа.

Особенности журнала:

* Запись создаётся для каждого подключения с клиентским ключом.
* Подключения с обычным ключом базы данных в журнал не попадают.
* Запись создаётся до проверки ключа. Попытка подключения с повреждённым клиентским ключом тоже попадает в журнал.

=== Замена ключа клиента

В плагине нет списка отозванных ключей. Отключить один клиентский ключ нельзя.

Чтобы закрыть доступ клиенту, у которого есть ключ:

. Расшифруйте базу данных и зашифруйте её новым ключом (см. <<fbcrypt-usage>>).
. Создайте новые клиентские ключи для нового ключа базы данных.
. Выдайте новые ключи остальным клиентам.

Пример работы с клиентскими ключами находится в каталоге `examples/clientkeygen` репозитория https://github.com/IBSurgeon/FirebirdEncryptionGuide[FirebirdEncryptionGuide].
