[[fbcrypt-monitoring]]
= Как отслеживать ход шифрования

Firebird шифрует базу данных только тогда, когда у неё есть активные соединения. Процесс шифрования выполняется в отдельном параллельном потоке, и для больших баз данных полное шифрование может занять значительное время.

== Таблица MON$DATABASE

Чтобы отслеживать процесс шифрования, выполните SQL-запрос к таблице мониторинга `MON$DATABASE`:

[source,sql]
----
select mon$crypt_page * 100.0 / mon$pages as Percent from mon$database;
commit;
----

Поле `MON$CRYPT_PAGE` содержит номер страницы, до которой дошёл поток шифрования. Когда шифрование завершено, поле равно `0`.

Таблицы мониторинга показывают снимок на момент первого обращения в транзакции. Чтобы увидеть новое значение, завершите транзакцию (`commit`) и выполните запрос снова.

В Firebird 4.0 и 5.0 есть также поле `MON$CRYPT_STATE`:

[source,sql]
----
select mon$crypt_state from mon$database;
----

[cols="1,3", options="header"]
|===
| Значение | Состояние
| `0` | база данных не зашифрована
| `1` | база данных зашифрована
| `2` | идёт расшифровка
| `3` | идёт шифрование
|===

== isql

Команда `show database` выводит одну из строк:

[cols="2,3", options="header"]
|===
| Строка | Состояние
| `Database not encrypted` | база данных не зашифрована
| `Database encrypted, crypt thread not complete` | шифрование запущено, но не завершено
| `Database encrypted` | шифрование завершено
|===

== gstat

Команда `gstat -h` показывает атрибуты заголовка: признак `encrypted`, имя плагина и имя ключа. Она работает быстро.

== Если шифрование не продвигается

* Проверьте, что к базе данных есть хотя бы одно подключение. Без подключений поток шифрования не работает.
* Проверьте, что подключение передало ключ или ключ доступен серверу.
* Посмотрите сообщения в `firebird.log`.
