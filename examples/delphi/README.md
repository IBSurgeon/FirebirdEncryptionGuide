# Примеры для Delphi

Компоненты: FireDAC из состава RAD Studio. Драйвер Firebird работает через `fbclient` (ISC API).
Ключ передаёт библиотека `fbcrypt` с защищённым обменом (способ A). Параметр `UnsafeClient = true` на сервере не нужен.

## Что нужно

- Delphi 10.4 Sydney или новее. Проверено с RAD Studio 11 (компилятор 35.0), платформы Win32 и Win64.
- Команда `dcc64` в `PATH`. Установщик RAD Studio добавляет каталог `bin`. Для Win32 нужна команда `dcc32`.
- Тестовый сервер: см. [../common/README.md](../common/README.md). Перед запуском загрузите `test-env.ps1`.

Разрядность программы должна совпадать с разрядностью `fbclient` и `fbcrypt`.
В клиентском каталоге должна лежать OpenSSL с именем, которое ищет `fbcrypt` (см. «Порядок загрузки библиотек»). Скрипт `setup.ps1` проверяет это сам.

```powershell
cd console-firedac
```

```powershell
dcc64 -B -Q -U..\common -N0lib -E. ConsoleFireDAC.dpr
```

```powershell
.\ConsoleFireDAC.exe
```

Перед сборкой создайте каталог `lib`: в него идут скомпилированные модули.

В RAD Studio откройте файл `.dproj`. Каталог `..\common` уже включён в пути поиска модулей. Файлы проектов записаны с ProjectVersion 18.7. Проекты проверены в RAD Studio 11; открытие в Delphi 10.4 не проверялось.

## Правила работы с fbcrypt

1. Компоненты доступа и `fbcrypt` должны использовать один `fbclient`. Пример задаёт каталог в `TFDPhysFBDriverLink.VendorHome` (`VendorLib = 'fbclient.dll'`) и передаёт тот же каталог в `TFbCrypt.Create`.
2. Вызывайте `TFbCrypt.RegisterForThread` в том потоке, который открывает подключение, перед `Connected := True`. Поток без вызова получает `Key not set` — это показывает `threads-firedac`.
3. Список ключей общий для процесса. `ClearKeys` удаляет все ключи, но обратный вызов остаётся зарегистрированным в потоке.
4. `fbcrypt_init` вызывается один раз для одного каталога. Чтобы взять другой каталог `fbclient`, перезапустите программу.
5. Для кода на объектно-ориентированном API используйте `RegisterForProvider`.

## Порядок загрузки библиотек

`fbcrypt.dll` импортирует `fbclient.dll`, а OpenSSL загружает по имени. Поэтому класс `TFbCrypt` загружает по полному пути в таком порядке:

1. `fbclient.dll` — без него `LoadLibrary` для `fbcrypt.dll` даёт ошибку 126;
2. `libcrypto-*.dll` — без него Firebird 3.0 и 4.0 отвечают `Key not set` на каждом подключении;
3. `fbcrypt.dll`.

Какую OpenSSL ищет `fbcrypt`:

| Firebird | 64 бита | 32 бита |
|---|---|---|
| 3.0, 4.0 | `libcrypto-1_1-x64.dll` | `libcrypto-1_1.dll` |
| 5.0 | `libcrypto-3-x64.dll` или `libcrypto-1_1-x64.dll` | `libcrypto-3.dll` или `libcrypto-1_1.dll` |

Если такая библиотека есть в `PATH` (например, `libcrypto-1_1-x64.dll` из Git for Windows), ошибка на машине разработчика будет замаскирована, а на другой машине пример не пройдёт.

Скрипт `setup.ps1` читает имена из самого `fbcrypt.dll` и кладёт OpenSSL в клиентский каталог под нужным именем. Если подходящей библиотеки нет, он останавливается с сообщением. Подробности: [../common/README.md](../common/README.md).

## Пул подключений FireDAC

- Пул включается параметром `Pooled=True` именованного определения подключения, которое добавлено в `FDManager`. У подключения `TFDConnection` свойства `Pooled` нет: подключение с параметрами и без определения даёт ошибку 507 «cannot be pooled».
- В проекте нужна единица `FireDAC.Stan.Pool`. Без неё первое подключение из пула даёт ошибку «Object factory ... is missing».
- Поток без `RegisterForThread`, который взял из пула уже открытое подключение, работает без ошибки: подключение уже открыто с ключом.

## gbak и версия Firebird

- Firebird 4.0 и 5.0: `gbak -KeyHolder KeyHolderStdin`, ключ записывается в стандартный ввод процесса.
- Firebird 3.0: переключателя `-KeyHolder` нет. Пример создаёт временный файл ключа в каталоге текущего пользователя и вызывает `gbak -KEYFILE <файл> -KEYNAME <имя>`, затем удаляет файл.

## vcl-firedac

Запуск без параметров открывает окно. В поле «Client folder» укажите каталог с `fbclient.dll`, `fbcrypt.dll` и OpenSSL.

- **Ключ.** Введите имя и значение или нажмите «Load key file...». Файл имеет формат `KeyHolder.conf` (`Key=<имя> 0x..,0x..,`). Файл, сохранённый кнопкой «Save as DPAPI protected file...», читает только тот же пользователь Windows на том же компьютере.
- **Encrypt, Decrypt, Change key.** Полоса прогресса и состояние берутся из `MON$DATABASE`. Подключение остаётся открытым, пока работает поток шифрования сервера. Смена ключа — это расшифровка и шифрование новым ключом.
- **Firebird 3.0.** В `MON$DATABASE` нет столбца `MON$CRYPT_STATE`, поэтому эти три кнопки выключены. Подключение и чтение данных работают.

Режим `--test` запускает сценарий S5 без окна и печатает те же строки, что примеры на других языках:

```powershell
.\VclFireDAC.exe --test
```
