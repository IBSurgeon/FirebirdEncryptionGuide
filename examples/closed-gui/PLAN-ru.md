# План: руководство по шифрованию для GUI-приложения с закрытыми исходными кодами

Редакция 5 от 24.11.2026. Статус: этапы 0–7 выполнены. Остался этап 8: релиз 1.2.

## 1. Цель

Понятное руководство для Windows с готовым примером.
Читатель выполняет несколько команд и получает работающую систему: сервер Firebird 3, 4 или 5, зашифрованная база `employee`, GUI-приложение без кода шифрования и библиотека `KeySource.dll`, которая передаёт ключ.

Результаты:

1. Документ «Шифрование для приложения без исходных кодов» (русский язык, PDF и исходный текст AsciiDoc).
2. Каталог `examples/closed-gui` с приложением, четырьмя библиотеками `KeySource.dll`, поставщиком ключа, демо-сервером REST и скриптами развёртывания.
3. Автоматическая проверка примера на Firebird 3.0, 4.0, 5.0.
4. Релиз 1.2 с PDF и готовыми программами.

## 2. Ревью по исходным кодам

Прочитаны исходные тексты плагина и Firebird: 3.0, 4.0 и 5.0 (HQbird).
Файлы: `plugins/crypt/db/holder/KeyHolder.cpp`, `AskPass.cpp`, `lib/hexKey.cpp`, `remote/client/interface.cpp`, `remote/server/server.cpp`, `jrd/CryptoManager.cpp`, `common/utils.cpp`, `common/os/win32/mod_loader.cpp`, а также `ibase60.inc` из FPC.

### 2.1. Что нашло ревью

| № | Факт из кода | Что изменено в плане |

### 4.1. Приложение `EmployeeApp`

Имитирует приложение без исходных кодов. В коде нет ни одного вызова, связанного с шифрованием.

- Одна форма: параметры подключения, кнопки «Подключиться» и «Отключиться», таблица с данными, навигатор, кнопки «Сохранить» и «Отменить».
- Данные: таблица `CUSTOMER` базы `employee`. Строки можно менять, добавлять и удалять.
- Строка состояния: версия сервера, протокол, состояние шифрования базы (`MON$CRYPT_STATE`).
- Библиотека доступа: SQLdb (`TIBConnection`). Входит в Lazarus. Работает через старый ISC API, как большинство старых приложений.
- Два режима сборки из одного исходного текста:
  - `EmployeeRemote.exe`: поля сервер, порт, база, пользователь, пароль.
  - `EmployeeEmbedded.exe`: поля файл базы и пользователь. Работает без сервера.
- Программа загружает `fbclient.dll` из своего каталога. Режим embedded задаёт строка `Providers = Engine12` (3.0) или `Engine13` (4.0, 5.0) в `firebird.conf` рядом с программой.
- Параметры сохраняются в `EmployeeApp.ini` рядом с программой.

### 4.2. Библиотеки `KeySource.dll`

Все четыре библиотеки написаны на Free Pascal и экспортируют одну функцию `MakeKeys` (`cdecl`). Внешних dll не требуют. Один исходный текст для Firebird 3.0, 4.0, 5.0.

| Вариант | Откуда ключ | Где кэш | От чего защищает | Слабое место |
|---|---|---|---|---|
| а) `a-static` | константа в коде библиотеки | не нужен | кража файла базы и резервных копий | ключ можно извлечь из dll |
| б) `b-file` | файл по пути из `KeySource.ini` (диск USB, сетевая папка с правами) | не нужен, файл читается при каждом вызове | то же; ключ отделён от программы | файл ключа можно скопировать |
| в) `c-provider` | поставщик ключа через именованный канал | у поставщика ключа | ключа нет на диске; ключ вводит человек | ключ в памяти поставщика до выхода |
| г) `d-rest` | служба ключей по HTTPS (WinHTTP) | в dll, которая закрепила себя в процессе; срок хранения в `KeySource.ini` | центральная выдача, отзыв, журнал | нужна сеть; нужна защита токена |

Общие правила. Они следуют из раздела 2.1:

- Библиотека выгружается после каждого вызова. Состояние между вызовами хранит только вариант «г», и только после закрепления dll.
- Библиотека не создаёт потоков и не оставляет открытых дескрипторов после выхода из `MakeKeys`.
- `MakeKeys` работает из нескольких потоков одновременно. Кэш варианта «г» защищён критической секцией.
- `MakeKeys` возвращает только ключи, нужные этому рабочему месту. Клиент отправляет серверу все полученные ключи.
- Память для ответа выделяется только функцией `allocator`.
- При ошибке библиотека возвращает `NULL` и пишет причину в журнал `KeySource.log` (включается в `KeySource.ini`). Ключ в журнал не пишется.
- `KeySource.ini` лежит рядом с dll. Путь dll определяет сама библиотека (`GetModuleFileName`).
- `KeySource.dll` рабочего места не копируется на сервер: серверный `KeyHolder` тоже вызывает `MakeKeys`, если находит библиотеку.

### 4.3. Поставщик ключа `KeyProvider.exe` (вариант «в»)

- Приложение Lazarus. После запуска сворачивается в трей Windows.
- При первом запросе показывает окно ввода. Пользователь вводит парольную фразу или ключ в формате `0x..,`.
- Проверяет ввод до отправки: формат ключа; во фразе запрещены `#`, `"`, `$(`; пробелы по краям удаляются. Фраза передаётся в UTF-8.
- Хранит ключ в памяти. Меню в трее: «Ввести ключ», «Забыть ключ», «Время хранения», «Выход».
- Связь: именованный канал `\\.\pipe\FbKeyProvider-<пользователь>`. Доступ только для текущего пользователя, удалённые клиенты запрещены.
- Протокол: одна строка запроса, ответ в формате текста ключей. Описание протокола входит в руководство.
- `KeySource.dll` обращается к каналу при каждом вызове `MakeKeys`. Ответ из кэша поставщика приходит без окна.
- Если поставщик не запущен, `KeySource.dll` запускает его (путь в `KeySource.ini`) или возвращает `NULL`.
- Неверный ключ: сервер возвращает ошибку ключа. Пользователь выбирает «Забыть ключ» и подключается снова.

### 4.4. Демо-сервер REST (вариант «г»)

- Скрипт `key-server.ps1` на `HttpListener`. Установка программ не нужна.
- `GET /keys/<имя>` с заголовком `Authorization: Bearer <токен>`. Ответ: текст ключей.
- Для примера: `http://localhost:8085`, тестовый токен в файле настроек.
- `KeySource.dll` запрашивает ключ один раз, закрепляет себя в процессе и хранит ключ в памяти заданное время. Тайм-аут запроса задан в `KeySource.ini`.
- Руководство описывает требования к рабочей службе: HTTPS, проверка сертификата, токен вне dll, журнал выдачи, отзыв доступа.

### 4.5. Скрипты развёртывания (`deploy/`)

Скачивание и копирование разделены. Каждый скрипт делает один шаг и принимает `-Version 3|4|5` и `-Bits 64|32`.

| Скрипт | Что делает |
|---|---|
| `01-download-firebird.ps1` | скачивает zip с `github.com/FirebirdSQL/firebird/releases`, проверяет SHA-256 |
| `02-download-plugin.ps1` | скачивает архив плагина с `cc.ib-aid.com`, проверяет состав, печатает SHA-256. `-Force` скачивает новый архив |
| `03-download-license.ps1` | берёт пробную лицензию из архива плагина или из `-Url`, `-LicenseFile`. Проверяет срок действия |
| `10-install-server.ps1` | распаковывает Firebird в `work\fb<N>\server`, копирует файлы плагина и лицензию, пишет `firebird.conf` (свой порт, `KeyHolderPlugin`) |
| `11-start-server.ps1`, `12-stop-server.ps1` | запускают и останавливают сервер как приложение. Права администратора не нужны |
| `20-encrypt-database.ps1` | при остановленном сервере копирует `employee.fdb`, шифрует ключом `Red`, ждёт окончания шифрования, удаляет ключ с сервера. Делает две копии: для сервера и для embedded |
| `30-build.ps1` | собирает приложение, библиотеки и поставщика ключа (`lazbuild`) |
| `40-deploy-remote.ps1 -KeySource a|b|c|d` | собирает каталог рабочего места: программа, клиент Firebird, `KeyHolder`, `KeySource.dll`, `firebird.conf` с `Providers = Remote` и `KeyHolderPlugin = KeyHolder` |
| `41-deploy-embedded.ps1 -KeySource a|b|c|d` | собирает каталог embedded: программа, движок, `DbCrypt`, `KeyHolder`, лицензия, `KeySource.dll`, своя копия базы |
| `run-all.ps1` | выполняет все шаги подряд |
| `cleanup.ps1` | останавливает сервер и удаляет `work\fb<N>` |

- Порты по умолчанию: 30053 (Firebird 3), 30054 (Firebird 4), 30055 (Firebird 5). Серверы разных версий работают одновременно и не мешают установленному Firebird.
- Версии, адреса, порты и контрольные суммы архивов Firebird записаны в одном файле `deploy\versions.psd1`.
- Готовы в черновом виде: `01`, `02`, `03`, `10`, `11`, `12`, `20`, `40`, `41`. Скрипты `40` и `41` пока принимают путь к dll (`-KeySourceDll`).
- На сервере ключей нет: в `KeyHolder.conf` нет строк `Key`, в каталоге сервера нет `KeySource.dll`. Ключ приходит от рабочего места.
- Embedded работает со своей копией базы. Движок embedded и сервер не открывают один файл одновременно.
- Скрипты запуска очищают переменную окружения `FIREBIRD` для своих процессов.
- Рабочее место 3.0 использует `fbclient.dll` из архива плагина. Для единообразия так же сделано в 4.0 и 5.0.

## 5. Содержание руководства

1. Задача. Что защищает шифрование и что не защищает.
2. Как ключ попадает к базе данных. Обычное подключение и embedded.
3. Отличия Firebird 3, 4, 5: файлы, провайдеры, параметры, утилиты.
4. Быстрый старт: одна команда `run-all.ps1`.

## 7. Проверка

Матрица: 3 версии × 2 режима × 4 варианта = 24 сочетания.

- Все 24 сочетания: проверка без окна. `isql` из каталога рабочего места читает `CUSTOMER` (тот же `fbclient` и тот же `KeySource.dll`).
- GUI: `EmployeeApp` запускается, подключается, меняет строку, читает её после повторного подключения. Минимум 6 сочетаний (каждая версия × режим с вариантом «а») и варианты «в», «г» на Firebird 5.0. Снимки экрана идут в руководство.
- Нагрузка: 1000 подключений подряд и 8 потоков одновременно с каждой dll. Нет сбоев, память процесса не растёт.
- Вариант «г»: за 100 подключений сервер ключей получает один запрос.
- Отрицательные проверки: нет `KeySource.dll`; неверный ключ; ошибка формата текста ключей; нет файла ключа; поставщик ключа закрыт; служба REST недоступна; неверный токен.
- На сервере нет ключа: клиент без `KeySource.dll` получает ошибку ключа. Проверить два случая: к базе никто не подключён; к базе подключён клиент с ключом.

Не входит в проверку: Linux, Delphi, сервер как служба Windows, рабочая служба ключей.

## 8. Принятые решения

Все рекомендации приняты 24.11.2026.

| № | Вопрос | Решение |
|---|---|---|
| 1 | Библиотека доступа в приложении: SQLdb или IBX | SQLdb: сборка без дополнительных пакетов |
| 2 | Нужны ли 32-битные сборки | Сначала 64 бита. 32 бита отдельным шагом: нужен кросс-компилятор FPC `i386-win32` (установщик с правами администратора). Скрипты сразу принимают `-Bits 32` |
| 3 | Отдельный документ или глава в `fbcrypt.pdf` | Отдельный PDF `fbcrypt-closed-gui.pdf` и ссылка из раздела `KeySource` основного руководства |
| 4 | Язык | Русский. Английский перевод после проверки текста |
| 5 | Тестовая лицензия: это `DbCrypt.conf` из архива плагина или отдельный файл | Брать из архива. Если лицензия из архива просрочена, запросить адрес действующего файла |
| 6 | Демо-сервер REST: скрипт PowerShell или программа Lazarus | Скрипт PowerShell |
| 7 | Версии Firebird | Последние официальные: 3.0.14, 4.0.7, 5.0.4. Номера записаны в `versions.psd1` |
| 8 | Таблица в приложении | `CUSTOMER`: нет вычисляемых полей, строки легко менять |
