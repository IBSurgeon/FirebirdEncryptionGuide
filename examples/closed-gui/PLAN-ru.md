# План: руководство по шифрованию для GUI-приложения с закрытыми исходными кодами

Редакция 2 от 24.11.2026. Статус: решения приняты, исполнение не начато.

## 1. Цель

Понятное руководство для Windows с готовым примером.
Читатель выполняет несколько команд и получает работающую систему: сервер Firebird 3, 4 или 5, зашифрованная база `employee`, GUI-приложение без кода шифрования и библиотека `KeySource.dll`, которая передаёт ключ.

Результаты:

1. Документ «Шифрование для приложения без исходных кодов» (русский язык, PDF и исходный текст AsciiDoc).
2. Каталог `examples/closed-gui` с приложением, четырьмя библиотеками `KeySource.dll`, поставщиком ключа, демо-сервером REST и скриптами развёртывания.
3. Автоматическая проверка примера на Firebird 3.0, 4.0, 5.0.
4. Релиз 1.2 с PDF и готовыми программами.

## 2. Проверенные факты

| Факт | Источник |
|---|---|
| `KeyHolder` загружает `KeySource` из каталога библиотек Firebird и вызывает `MakeKeys` в конструкторе плагина. Код одинаков в 3.0 и 4.0 | `src/plugins/crypt/db/holder/KeyHolder.cpp` |
| Если `MakeKeys` вернула `NULL`, плагин берёт ключи из `KeyHolder.conf` | там же |
| Текст ключей: строки `Key=<имя> 0x..,` и `Password=<имя> <фраза>` | руководство, раздел `fbcrypt-keysource` |
| Архивы плагина для Windows доступны, 32 и 64 бита, версии 3.0, 4.0, 5.0 (дата файлов 01.10.2026) | `https://cc.ib-aid.com/download/distr/crypt/CryptPlugin-FB_<30,40,50>_WINDOWS_<32,64>bit.zip` |
| Архив плагина содержит пробную лицензию `Server\plugins\DbCrypt.conf` | руководство, раздел «Файл лицензии» |
| Последние официальные сборки: 3.0.14.33856, 4.0.7.3271, 5.0.4.1812 (zip для x64 и Win32) | `https://github.com/FirebirdSQL/firebird/releases` |
| Экземпляр `KeyHolder` создаётся заново: на клиенте для каждого соединения (`remote.h`, `pluginItr`), в движке при каждом подключении к базе (`CryptoManager.cpp`). Значит, `MakeKeys` вызывается много раз за время работы программы. Код одинаков в 3.0 и 4.0 | исходный код Firebird с плагином |
| Клиентский `KeySource` уже проверен с `isql`, Python, PHP, Java на Firebird 4.0 и 5.0 | тесты `examples/*/…keysource` |

## 3. Что нужно проверить до начала (этап 0)

1. Сколько раз вызывается `MakeKeys` при одном подключении. По коду: не меньше одного раза на каждое подключение (см. раздел 2). Точное число измерить журналом `KeySource.log` на клиенте и в embedded, в версиях 3, 4, 5. Кэш в памяти dll для вариантов «в» и «г» обязателен.
2. Можно ли в `MakeKeys` ждать ответа пользователя 1–2 минуты (вариант «в»). Нет ли блокировки или тайм-аута.
3. Действует ли пробная лицензия из архивов от 01.10.2026. Если нет, нужен адрес файла тестовой лицензии (вопрос 5).
4. Совместим ли плагин из архива с официальными сборками 3.0.14, 4.0.7, 5.0.4. Нужен ли `fbclient.dll` из архива плагина или подходит официальный.
5. Минимальный набор файлов для embedded с шифрованием (движок, `DbCrypt`, `KeyHolder`, лицензия, OpenSSL, `KeySource.dll`).
6. Работает ли клиентский `KeySource` на Firebird 3.0 так же, как на 4.0 и 5.0.

Результат этапа 0: таблица ответов в этом плане. Если ответ меняет решение, план исправляется до начала работ.

## 4. Состав примера

```
examples/closed-gui/
  README.md            короткая инструкция и ссылка на PDF
  app/EmployeeApp/     приложение Lazarus, режимы сборки Remote и Embedded
  keysource/
    common/            общий модуль: MakeKeys, сборка текста ключей, журнал
    a-static/          ключ в тексте библиотеки
    b-file/            ключ из файла
    c-provider/        запрос ключа у поставщика ключа
    d-rest/            запрос ключа по REST
  keyprovider/         поставщик ключа: приложение Lazarus в трее Windows
  restserver/          демо-сервер ключей: key-server.ps1
  deploy/              скрипты скачивания, установки, запуска
  tests/               автоматические проверки
```

Двоичные файлы плагина, Firebird и файл лицензии в репозиторий не попадают. Скрипты кладут их в каталог `work\`, который закрыт в `.gitignore`.
Во всех примерах используется открытый тестовый ключ `Red` из `examples/common/test-keys.conf`.

### 4.1. Приложение `EmployeeApp`

Имитирует приложение без исходных кодов. В коде нет ни одного вызова, связанного с шифрованием.

- Одна форма: параметры подключения, кнопки «Подключиться» и «Отключиться», таблица с данными, навигатор, кнопки «Сохранить» и «Отменить».
- Данные: таблица `CUSTOMER` базы `employee`. Строки можно менять, добавлять и удалять.
- Строка состояния: версия сервера, протокол, состояние шифрования базы (`MON$CRYPT_STATE`).
- Библиотека доступа: SQLdb (`TIBConnection`). Входит в Lazarus, дополнительные пакеты не нужны.
- Два режима сборки из одного исходного текста:
  - `EmployeeRemote.exe`: поля сервер, порт, база, пользователь, пароль.
  - `EmployeeEmbedded.exe`: поля файл базы и пользователь. Работает без сервера.
- Параметры сохраняются в `EmployeeApp.ini` рядом с программой.

### 4.2. Библиотеки `KeySource.dll`

Все четыре библиотеки написаны на Free Pascal и экспортируют одну функцию `MakeKeys` (`cdecl`). Внешних dll не требуют.

| Вариант | Откуда ключ | Настройка | От чего защищает | Слабое место |
|---|---|---|---|---|
| а) `a-static` | константа в коде библиотеки | нет | кража файла базы и резервных копий | ключ можно извлечь из dll |
| б) `b-file` | файл по пути из `KeySource.ini` | путь к файлу (диск USB, сетевая папка с правами) | то же; ключ отделён от программы | файл ключа можно скопировать |
| в) `c-provider` | поставщик ключа через именованный канал | имя канала, тайм-аут | ключа нет на диске; ключ вводит человек | ключ в памяти поставщика до выхода |
| г) `d-rest` | служба ключей по HTTPS (WinHTTP) | адрес, токен, тайм-аут | центральная выдача, отзыв, журнал | нужна сеть; нужна защита токена |

Общие правила для всех вариантов:

- Память для ответа выделяется только функцией `allocator`.
- При ошибке библиотека возвращает `NULL` и пишет причину в журнал `KeySource.log` (включается в `KeySource.ini`). Ключ в журнал не пишется.
- Варианты «в» и «г» хранят полученный ключ в памяти процесса. Повторные вызовы `MakeKeys` не обращаются к поставщику и к сети.

### 4.3. Поставщик ключа `KeyProvider.exe` (вариант «в»)

- Приложение Lazarus. После запуска сворачивается в трей Windows.
- При первом запросе показывает окно ввода. Пользователь вводит парольную фразу или ключ в формате `0x..,`.
- Хранит ключ в памяти. Меню в трее: «Ввести ключ», «Забыть ключ», «Время хранения», «Выход».
- Связь: именованный канал `\\.\pipe\FbKeyProvider-<пользователь>`. Доступ только для текущего пользователя, удалённые клиенты запрещены.
- Протокол: одна строка запроса, ответ в формате текста ключей. Описание протокола входит в руководство.
- Если поставщик не запущен, `KeySource.dll` запускает его (путь в `KeySource.ini`) или возвращает `NULL`.

### 4.4. Демо-сервер REST (вариант «г»)

- Скрипт `key-server.ps1` на `HttpListener`. Установка программ не нужна.
- `GET /keys/<имя>` с заголовком `Authorization: Bearer <токен>`. Ответ: текст ключей.
- Для примера: `http://localhost:8085`, тестовый токен в файле настроек.
- Руководство описывает требования к рабочей службе: HTTPS, проверка сертификата, токен вне dll, журнал выдачи, отзыв доступа.

### 4.5. Скрипты развёртывания (`deploy/`)

Скачивание и копирование разделены. Каждый скрипт делает один шаг и принимает `-Version 3|4|5` и `-Bits 64|32`.

| Скрипт | Что делает |
|---|---|
| `01-download-firebird.ps1` | скачивает zip с `github.com/FirebirdSQL/firebird/releases`, проверяет SHA-256 |
| `02-download-plugin.ps1` | скачивает архив плагина с `cc.ib-aid.com`, проверяет размер и SHA-256 |
| `03-download-license.ps1` | берёт пробную лицензию из архива плагина или скачивает её по отдельному адресу |
| `10-install-server.ps1` | распаковывает Firebird в `work\fb<N>\server`, копирует файлы плагина и лицензию, пишет `firebird.conf` (свой порт, `KeyHolderPlugin`) |
| `11-start-server.ps1`, `12-stop-server.ps1` | запускают и останавливают сервер как приложение. Права администратора не нужны |
| `20-encrypt-database.ps1` | копирует `employee.fdb`, шифрует ключом `Red`, ждёт окончания шифрования |
| `30-build.ps1` | собирает приложение, библиотеки и поставщика ключа (`lazbuild`) |
| `40-deploy-remote.ps1 -KeySource a|b|c|d` | собирает каталог рабочего места: программа, клиент Firebird, `KeyHolder`, `KeySource.dll` |
| `41-deploy-embedded.ps1 -KeySource a|b|c|d` | собирает каталог embedded: программа, движок, плагины, лицензия, `KeySource.dll` |
| `run-all.ps1` | выполняет все шаги подряд |
| `cleanup.ps1` | останавливает сервер и удаляет `work\fb<N>` |

Порты по умолчанию: 3053 (Firebird 3), 3054 (Firebird 4), 3055 (Firebird 5). Серверы разных версий работают одновременно и не мешают установленному Firebird.
Версии и контрольные суммы файлов записаны в одном файле `deploy\versions.psd1`.
На сервере ключей нет: в `KeyHolder.conf` нет строк `Key`. Ключ приходит от рабочего места.

## 5. Содержание руководства

1. Задача. Что защищает шифрование и что не защищает.
2. Как ключ попадает к базе данных. Обычное подключение и embedded.
3. Отличия Firebird 3, 4, 5: файлы, провайдеры, параметры, утилиты.
4. Быстрый старт: одна команда `run-all.ps1`.
5. Развёртывание по шагам: скачивание, сервер, шифрование базы, рабочее место.
6. Приложение-пример.
7. Четыре варианта `KeySource.dll`. Для каждого: схема, код, настройка, проверка, риски.
8. Сравнение вариантов. Какой выбрать.
9. Перенос на своё приложение: разрядность, откуда приложение загружает `fbclient.dll`, установщик, обновление.
10. Смена ключа, потеря ключа, резервные копии (кратко, со ссылками на основное руководство).
11. Диагностика: типовые ошибки и журнал `KeySource.log`.

## 6. Этапы

| Этап | Работа | Готово, когда |
|---|---|---|
| 0 | Проверка фактов из раздела 3 | таблица ответов в плане |

| 2 | `EmployeeApp`, два режима сборки | программа открывает незашифрованную базу, изменения сохраняются |
| 3 | `KeySource` «а» и «б», скрипты `40` и `41` | программа открывает зашифрованную базу в обоих режимах |

## 7. Проверка

Матрица: 3 версии × 2 режима × 4 варианта = 24 сочетания.

- Все 24 сочетания: проверка без окна. `isql` из каталога рабочего места читает `CUSTOMER` (тот же `fbclient` и тот же `KeySource.dll`).
- GUI: `EmployeeApp` запускается, подключается, меняет строку, читает её после повторного подключения. Минимум 6 сочетаний (каждая версия × режим с вариантом «а») и варианты «в», «г» на Firebird 5.0. Снимки экрана идут в руководство.
- Отрицательные проверки: нет `KeySource.dll`; неверный ключ; нет файла ключа; поставщик ключа закрыт; служба REST недоступна; неверный токен.
- На сервере нет ключа: после отключения всех клиентов новое подключение без `KeySource` не открывает базу.

Не входит в проверку: Linux, Delphi, сервер как служба Windows, рабочая служба ключей.

## 8. Принятые решения

Все рекомендации приняты 24.11.2026.

| № | Вопрос | Решение |
|---|---|---|
| 1 | Библиотека доступа в приложении: SQLdb или IBX | SQLdb: сборка без дополнительных пакетов |
| 2 | Нужны ли 32-битные сборки | Сначала 64 бита. 32 бита отдельным шагом: нужен кросс-компилятор FPC `i386-win32` (установщик с правами администратора). Скрипты сразу принимают `-Bits 32` |
| 3 | Отдельный документ или глава в `fbcrypt.pdf` | Отдельный PDF `fbcrypt-closed-gui.pdf` и ссылка из раздела `KeySource` основного руководства |
| 4 | Язык | Русский. Английский перевод после проверки текста |
| 5 | Тестовая лицензия: это `DbCrypt.conf` из архива плагина или отдельный файл | Брать из архива. Если лицензия из архива просрочена, запросить адрес действующего файла |
| 6 | Демо-сервер REST: скрипт PowerShell или программа Lazarus | Скрипт PowerShell |
| 7 | Версии Firebird | Последние официальные: 3.0.14, 4.0.7, 5.0.4. Номера записаны в `versions.psd1` |
| 8 | Таблица в приложении | `CUSTOMER`: нет вычисляемых полей, строки легко менять |

## 9. Риски

| Риск | Действие |
|---|---|
| Пробная лицензия в архиве просрочена | этап 0, пункт 3; запросить адрес действующей лицензии |
| Плагин не совместим с последней официальной сборкой | закрепить в `versions.psd1` версию, с которой плагин работает |
| `MakeKeys` вызывается часто или под блокировкой | кэш в памяти dll; окно ввода показывает поставщик, а не dll |
| Реальные закрытые приложения чаще 32-битные | вопрос 2; раздел руководства о разрядности |
| Пример воспринимают как готовую защиту | в каждом варианте раздел «Риски»; тестовый ключ и токен помечены как тестовые |
