# Индивидуальные ключи клиентов (ClientKeygen)

Только Firebird 5.0 (HQbird 5).

Утилита `ClientKeygen` создаёт из одного ключа базы данных отдельный ключ для каждого клиента.
Сервер по клиентскому ключу определяет номер клиента и записывает его в `firebird.log`.
Описание: руководство, раздел «Индивидуальные ключи клиентов».

## Что нужно

- Тестовый сервер Firebird 5.0: см. [../common/README.md](../common/README.md). Скрипт `setup.ps1` сам добавляет `Logger = true` в `DbCrypt.conf` сервера 5.0.
- Утилита `ClientKeygen`. Задайте полный путь к ней:

```powershell
$env:FBCRYPT_CLIENTKEYGEN = "C:\HQbird\tools\clientkeygen.exe"
```

- Python и пакет `firebird-driver`: см. [../python/README.md](../python/README.md).

## Запуск

```powershell
python main.py
```

Проверка: `.\run-test.ps1`. Без Firebird 5.0 или без переменной `FBCRYPT_CLIENTKEYGEN` скрипт пропускает тест.

## Что делает пример

1. Создаёт временный каталог с файлами `KeyHolder.conf` (ключ `Red`) и `DbCrypt.conf` (лицензия сервера).
2. Запускает `ClientKeygen Red 3`. Утилита создаёт файлы `KeyHolder.conf.1`, `KeyHolder.conf.2`, `KeyHolder.conf.3`.
3. Подключается к базе данных с каждым клиентским ключом через `fbcrypt`.
4. Находит в `firebird.log` записи вида `DbCrypt login from <адрес> using key <номер>`.
5. Показывает, что повреждённый клиентский ключ не открывает базу данных.
6. Удаляет временный каталог.

## Правила

- Клиентский ключ имеет длину 64 байта. Имя ключа то же, что у ключа базы данных.
- Ключ базы данных должен иметь длину 32 байта.
- Утилите нужна лицензия того сервера, для которого создаются ключи. На другом сервере клиентские ключи не работают.
- Каталог, в котором работает `ClientKeygen`, содержит ключ базы данных. Удалите его после работы.
- Обычный ключ базы данных продолжает работать. В журнал такие подключения не попадают.
- Запись в журнале создаётся до проверки ключа. Попытка с повреждённым ключом тоже попадает в журнал.
- Отключить один клиентский ключ нельзя. Чтобы закрыть доступ, зашифруйте базу данных новым ключом и выдайте новые клиентские ключи.

## Как клиент использует свой ключ

| Способ | Что сделать |
|---|---|
| `fbcrypt` | Передать значение в `fbcrypt_key` с длиной 64. |
| Клиентский плагин `KeyHolder` | Сохранить файл `KeyHolder.conf.<номер>` как `plugins\KeyHolder.conf` рядом с `fbclient`. В клиентском `firebird.conf` указать `KeyHolderPlugin = KeyHolder`. |
| `KeySource` | Вернуть строку из файла в функции `MakeKeys`. |
| Свойство драйвера (Jaybird, .NET) | Значение `<имя>:0x..,0x..,`. Нужен `UnsafeClient = true`. |

Проверены способы `fbcrypt`, клиентский `KeyHolder` и статическое значение.
